## 模式一：纯 Prompt Bot（高情商回复助手）

**难度**：⭐ | **核心技术**：角色设定 + 结构化 Prompt | **不需要**：插件、知识库、工作流

### 场景

职场沟通中需要拒绝同事请求，但不想伤害关系。通过精心设计的 Prompt 让 Bot 成为"高情商沟通专家"。

### Prompt 设计

```markdown
# 角色
你是一位经验丰富的沟通专家，拥有10年职场历练，在各类职场场景中都能游刃有余。
尤其擅长撰写高情商、得体且有效的沟通文本，在拒绝请求时，能巧妙地平衡关系与边界。

## 技能
### 技能 1: 语气把控
1. 以积极、友好的话语作为开头，营造融洽氛围。
2. 表达观点时，以"我"为主语阐述自身限制。
3. 杜绝使用指责性、命令式的语言。

### 技能 2: 内容构建
1. 率先表达对对方请求的理解以及诚挚的感谢。
2. 清晰、明确地说明自身存在的限制。
3. 根据实际情况，提供切实可行的替代方案或合理建议。
4. 以开放的态度，展望未来合作的可能性。

### 技能 3: 关系维护
1. 适时、恰当地表达歉意。
2. 真诚肯定对方工作的价值与贡献。
3. 始终保持专业且友善的态度。

## 输出格式
【开场寒暄】用积极友好的语言开启交流。
【表达理解与感谢】清晰传达对对方的理解与感激。
【委婉说明限制】明确阐述自身的限制条件。
【提供替代方案】给出具体的替代办法或建议。
【结尾祝福】以积极的话语结束对话，表达美好祝愿。

## 限制
- 避免使用"不""拒绝"等直接的负面词汇。
- 不可过度承诺或给予虚假安慰。
- 不贬低对方请求的合理性。
- 不过多解释个人情况。
```

### 效果对比

```
低情商 Prompt（"你是一个低情商回复助手，刚开始入职工作，不太擅长沟通"）：
  → "我没空，你自己想办法吧"

高情商 Prompt（上述设计）：
  → 【开场寒暄】Hi，感谢你想到我！
    【表达理解】我理解这个项目时间很紧，你能主动寻求帮助真的很负责任。
    【委婉说明】我目前手上有三个项目在赶 deadline，实在分身乏术。
    【替代方案】我推荐你找小李，他在这个领域很有经验；或者我们可以周五
    一起讨论一下框架思路？
    【结尾祝福】相信以你的能力一定能搞定，需要的话随时交流！
```

`★ Insight ─────────────────────────────────────`
**人设 Prompt 的本质是"软约束"**。LLM 不是硬编码程序，它不会 100% 遵守你的规则。但通过**角色设定 + 结构化输出格式 + 硬性限制**三层约束，可以大幅提高输出的可预测性。这就好比给新员工一份详细的岗位说明书——虽然不能保证他每个动作都按说明来，但大方向基本靠谱。

## 模式二：知识库 + Bot（英雄联盟助手）

**难度**：⭐⭐ | **核心技术**：知识库检索 + 角色扮演 | **新增**：知识库

### 场景

构建一个 LOL 游戏助手"小智"，能回答游戏攻略问题。知识来源于上传的游戏攻略文档。

### 架构

```
用户提问 → Bot → 知识库检索 → 召回相关内容 → LLM 判断+整理 → 回答
```

### System Prompt 设计要点

```markdown
# 角色
你叫小智，是一个英雄联盟游戏助手

## 技能
### 技能1：问题理解与回复分析
1. 认真理解从知识库中召回的内容和用户输入的问题，判断召回的内容是否
   是用户问题的答案。
2. 如果你不能理解用户的问题（如问题太简单、不包含必要信息），需要主动
   追问用户，直到确定已理解了用户的问题和需求。

### 技能2：回答用户问题
1. 如果知识库中没有召回任何内容，回复"对不起，我已经学习的知识中不包含
   问题相关内容，暂时无法提供答案。"
2. 如果召回的内容与用户问题有关，只提取知识库中和问题提问相关的部分，
   整理并总结。答案必须精确简洁，无需注明数据来源。
3. 判断用户的问题属于哪个文档的内容，把相应的文档名称一起返回给用户。

## 限制
- 禁止回答隐私信息（真实姓名、电话、地址、密码等）
- 禁止回答违法、违规内容（政治敏感、色情、暴力等）
- 回答长度不超过 300 字
- 必须使用 Markdown 格式回复
- 用与用户输入相同的语言回答
```

### 关键设计点

| 设计点 | 说明 | 为什么重要 |
|--------|------|-----------|
| **明确"无结果"话术** | 知识库没搜到时给固定回复 | 防止模型在不知道时胡编乱造 |
| **要求标注来源** | 返回时注明属于哪个文档 | 让用户知道信息出处，增加可信度 |
| **限制回答长度** | 不超过300字 | 防止模型过度发挥，偏离知识库内容 |
| **主动追问机制** | 问题不清楚时追问 | 确保理解用户意图再回答 |

## 模式三：多插件编排（AI 旅行规划助手）

**难度**：⭐⭐⭐ | **核心技术**：多插件协同调用 | **新增**：多个官方插件

### 场景

用户输入旅行需求，Bot 自动调用搜索引擎、高德地图、天气服务、计算器等插件，综合生成一份完整的旅行计划。

### 架构

```
用户输入旅行需求
    ↓
┌─────────────────────────────────────────────────────┐
│  LLM 根据 Prompt 自主决定调用哪些插件               │
├──────────┬──────────┬───────────┬───────────────────┤
│ 联网搜索  │ 高德地图  │ 墨迹天气  │ 简易计算器        │
│ 历史背景  │ 周边饭店  │ 出行天气  │ 费用预算          │
└──────────┴──────────┴───────────┴───────────────────┘
    ↓
汇总生成旅行计划
```

### 使用的插件

| 插件 | 功能 | 插件名 |
|------|------|--------|
| 联网问答 | 搜索名胜古迹历史 | `search_url` |
| 高德地图 | 搜索周边饭店 | `search_around` |
| 墨迹天气 | 获取出行天气 | `DayWeather` |
| 简易计算器 | 费用预算 | `calculate` |

### Prompt 关键设计

在 Prompt 中**用 `{插件名}` 标记引用插件**，并给出输出格式示例：

```markdown
### 技能 1: 深度探索名胜古迹历史
运用 {search_url} 插件精准挖掘相关历史信息，以生动易懂的方式呈现。

### 技能 2: 精准搜索周边特色饭店
借助 {search_around} 插件全面搜索相关信息，整理饭店名称、地址、特色菜品。
===回复示例===
- 饭店名称: <饭店具体名称>
- 地址: <详细地址>
- 特色菜品: <列举几道特色菜品>
===示例结束===

### 技能 3: 实时掌握出行天气
利用 {DayWeather} 插件获取目的地出行期间的准确天气状况。
若天气可能影响体验，给出合理的出行日期调整建议。

### 技能 4: 精细规划旅行费用预算
通过 {calculate} 插件进行精确的费用预算，全面覆盖交通、住宿、餐饮、门票。

## 输出格式
### 旅行计划
- 旅行目的地: <城市/地点>
- 地点文化历史: <描述名胜古迹历史>
- 出行时间: <开始日期 - 结束日期>
- 总预算: <金额>
- 天气情况: <天气描述>
- 行程安排:
    - 第 1 天: 上午… 中午… 下午… 晚上…
    - 第 2 天: …
- 特色饭店推荐: <饭店名称、地址、特色菜品>
```

**关键技巧**：通过 `===回复示例===` 告诉 LLM 期望的输出格式。这是比自然语言描述更精确的格式约束——LLM 更擅长模仿示例而非理解格式规则。

## 模式四：工作流编排（跨境电商答疑助手）

**难度**：⭐⭐⭐⭐ | **核心技术**：意图识别 + 选择器分流 + RAG | **新增**：工作流节点编排

### 场景

构建一个跨境电商答疑 Bot，能区分用户是打招呼、找人工客服、还是问专业问题，并走不同的处理路径。

### 工作流全景

```
开始（用户输入问题）
    ↓
意图识别（插件节点）
    ├── 打招呼 → 直接友好回复 → 结束
    ├── 找人工 → 返回客服链接 → 结束
    └── 专业问题 → 知识库检索
                    ├── 检索到结果 → 大模型 RAG 回答 → 结束
                    └── 无结果 → 大模型闲聊回答 → 结束
```

### 节点配置详情

| 序号 | 节点 | 类型 | 作用 |
|------|------|------|------|
| 1 | 开始 | 默认 | 接收用户 query |
| 2 | 意图识别 | 插件 | 判断：打招呼 / 找人工 / 专业问题 |
| 3 | 选择器1 | 选择器 | 打招呼/找人工 → 直接回复并结束；专业问题 → 继续 |
| 4 | 知识库检索 | 知识库 | 根据 query 检索相关文档片段 |
| 5 | 选择器2 | 选择器 | 有结果 → RAG 大模型；无结果 → 闲聊大模型 |
| 6 | RAG 大模型 | 大模型 | 基于上下文回答问题 |
| 7 | 闲聊大模型 | 大模型 | 基于自身知识回答问题 |
| 8 | 结束 | 默认 | 输出最终结果 |

### 意图识别插件代码

```python
from runtime import Args
import random

def handler(args) -> dict:
    """基于关键词匹配的意图识别"""
    query = args.input.query.strip()

    # 打招呼短语库
    greeting_phrases = {
        "你好", "您好", "hi", "hello", "嗨", "早上好", "下午好",
        "你是谁", "你叫什么", "介绍一下自己", "你能干什么"
    }
    # 告别短语库
    goodbye_phrases = {"再见", "拜拜", "bye", "bye bye"}
    # 人工服务短语库
    human_service_phrases = {
        "人工服务", "人工客服", "转人工", "找客服", "投诉",
        "退款", "退货", "售后", "联系老师"
    }

    # 精确匹配 + 包含匹配
    if any(p in query for p in greeting_phrases):
        return {"type": "greeting",
                "response": "你好！我是跨境电商学习小助手",
                "need_rag": False}
    if any(p in query for p in goodbye_phrases):
        return {"type": "greeting",
                "response": random.choice(["再见！", "下次见！"]),
                "need_rag": False}
    if any(p in query for p in human_service_phrases):
        return {"type": "human_service",
                "response": "点击 https://xxx.com 进入人工答疑",
                "need_rag": False}

    # 其他情况走 RAG 检索
    return {"type": "rag_needed", "response": "", "need_rag": True}
```

### 双模式大模型 Prompt

```
RAG 模式（有检索结果）：
  角色：跨境电商答疑小助手
  技能1：严格依据上下文回答
  技能2：答案太简单时进行润色，但不改变核心内容
  技能3：上下文不足时结合专业知识补充，标注"以上信息仅供参考"
  限制：仅回答跨境电商问题

闲聊模式（无检索结果）：
  角色：亲切的跨境电商答疑小助手，兼有通用知识
  技能1：精准解答电商专业问题
  技能2：耐心回应非电商问题（如"1+1等于几"）
  技能3：问题不明确时引导用户重新描述
  限制：禁止提及"需要进行知识库检索"
```

`★ Insight ─────────────────────────────────────`
**意图识别 + 选择器分流**是 Bot 开发中最重要的设计模式。一个 Bot 不可能用一个 Prompt 覆盖所有场景——用户可能打招呼、问专业问题、要求转人工，每种场景的处理逻辑完全不同。通过意图识别把流量分开，每个分支用专门的 Prompt 和工具，这是生产级 Bot 的标准做法。
`─────────────────────────────────────────────────`

## 模式五：多媒体生成工作流（历史人物视频生成）

**难度**：⭐⭐⭐⭐⭐ | **核心技术**：多节点编排 + 批处理 + 外部工具集成 | **新增**：图像生成、视频生成、剪映集成

### 场景

用户只需输入一个历史人物名字（如"拿破仑"），系统自动完成：生成生平文案 → 生成图片提示词 → 批量生成配图 → 生成视频提示词 → 批量生成视频 → 制作字幕/标题/音频 → 生成剪映草稿。**一句话变 MV**。

### 完整工作流（22 个节点）

```
用户输入人物名称
    ↓
[1] 大模型：生成人物生平文案 + 视频标题（输出 JSON）
    ↓
[2] 大模型：根据文案生成图片提示词（数组输出）
    ↓
[3] 批处理：逐条调用图像生成插件 → N 张图片
    ↓
[4] 代码：图片链接格式转换 + 去重（Array<Image> → Array<String>）
    ↓
[5] 批处理：根据图片提示词 + 文案 → 生成视频提示词
    ↓
[6] 批处理：图文生成视频（首帧图片 + 视频提示词）
    ↓
[7] get_url：提取视频链接
    ↓
[8] objs_to_str_list：对象列表 → 字符串列表
    ↓
[9] 代码：预估视频时间 + 有效数量
    ↓
[10] timelines：生成时间线
    ↓
[11] video_infos：制作视频数据
    ↓
[12] caption_infos：制作字幕数据
    ↓
[13] caption_infos：制作标题数据
    ↓
[14] str_to_list：配置背景音乐
    ↓
[15] audio_infos：制作音频数据
    ↓
[16] create_draft：创建剪映草稿
    ↓
[17] add_videos：批量添加视频
    ↓
[18] add_captions：批量添加字幕
    ↓
[19] add_captions：添加标题
    ↓
[20] add_audios：批量添加音频
    ↓
[21] 结束：输出 draft_id（可在剪映中打开编辑）
```

### 关键设计要点

| 环节 | 关键技巧 |
|------|---------|
| **文案生成** | 要求 LLM 输出结构化 JSON（`{content, title}`），方便下游节点消费 |
| **图片提示词** | 在用户 prompt 中追加风格描述："中国历史题材古代写实风格，超高清晰度" |
| **视频安全** | 视频提示词经过三级安全处理（详见下方） |
| **批处理** | 对数组逐条并发执行（生成图片/视频），是工作流的核心并发能力 |
| **格式转换** | 节点间数据格式不匹配时，用代码节点做中转 |
| **剪映集成** | 通过"剪映小助手"外部工具将 draft_id 导入剪映专业版 |

### 视频生成的安全处理

```markdown
## 核心安全准则
### 内容三级安全处理
- 第一层：直接移除禁用内容（暴力、血腥、危险动作）
- 第二层：弱化刺激性动作（"冲突"→"争论"、"战斗"→"技能展示"）
- 第三层：高风险场景替换（"战场"→"模拟演练区"、"处刑"→"舞台剧排练"）

### 替代词库
- "攻击" → "示范动作"
- "爆炸" → "舞台闪光效果"
- "死亡" → "人生阶段结束的象征性画面"
- "血迹" → "红色化妆颜料用于戏剧效果"

最终守则：所有内容必须符合"幼儿园可播放标准"
```

### 剪映小助手集成

2. 配置剪映草稿路径（必须与剪映专业版的草稿位置完全一致）
   剪映路径查找：剪映专业版 → 设置 → 全局设置 → 草稿位置
3. 工作流运行完成后，复制输出的 draft_id
4. 粘贴到剪映小助手

## 模式六：多源信息聚合（每日AI简报助手）

**难度**：⭐⭐⭐⭐ | **核心技术**：多插件数据源聚合 + 工作流编排 + 结构化输出 | **新增**：RSS、GitHub、arXiv 插件组合

### 场景

构建一个"每日AI简报"智能体，自动从多个信息源（36氪、虎嗅、IT之家、InfoQ、GitHub、arXiv）抓取当日最新的 AI 领域头条新闻、学术论文及开源项目动态，结构化整合成一份专业简报。

### 学到的核心技能

- **多源信息聚合**：利用 Coze 插件生态，实现跨平台、跨类型的数据流无缝集成
- **智能体行为定义**：通过角色设定和 Prompt 工程，精准控制任务执行与内容生成
- **自动化工作流构建**：将数据获取、内容处理、格式化输出串联为自动化流程

### 步骤一：添加并配置信息源插件

为 Bot 接入 4 类信息源插件：

| 信息源 | 插件 | 配置说明 |
|--------|------|---------|
| 科技媒体 RSS | RSS 订阅插件 | 配置 36氪、虎嗅、IT之家、InfoQ 的 RSS 链接 |
| GitHub 开源 | GitHub 插件 | `q: AI`, `per_page: 10`, `sort: updated` |
| 学术论文 | arXiv 插件 | `count: 5`, `search_query: AI`, `sort_by: 2` |

**RSS 链接配置**：

```
36氪：  https://www.36kr.com/feed
虎嗅：  https://rss.huxiu.com/
IT之家：http://www.ithome.com/rss/
InfoQ： https://feed.infoq.com/ai-ml-data-eng/
```

**GitHub 插件配置**：
```
q: AI
per_page: 10
sort: updated
```

**arXiv 插件配置**：
```
count: 5
search_query: AI
sort_by: 2
```

### 步骤二：设定角色与提示词

角色设定为**资深科技媒体编辑**，分为 System Prompt（长期行为准则）和 User Prompt（具体任务指令）。

**System Prompt**：

```markdown
# 角色
你是一位资深且权威的科技媒体编辑，擅长高效精准地整合并创作极具专业性的
科技简报，特别在AI领域的技术动态、前沿学术研究成果及热门开源项目方面
拥有深入的分析与整合能力。

## 工作流
### 日报输出格式
1. 日报开头显著标注"AI日报"、"by@作者名"和当天日期，
   例如："AI日报 | 2025年9月24日 | by@jasonhuang"
2. 根据每则内容的类型，在其标题开头添加一个独有的 Emoji 表情符号
3. 输出的所有内容必须与 AI、LLM、AIGC、大模型等技术主题高度相关，
   坚决排除任何无关信息、广告及营销类内容
4. 必须为每一条目提供其对应的原始链接
5. 对每一条新闻或项目进行简短、精准的概括描述
```

**User Prompt**：

```markdown
- 从 {{articles}}、{{articles1}}、{{articles2}}、{{articles3}} 中，
  筛选 AI/大模型/AIGC/LLM 相关文章，整理为"AI技术新闻"模块
- 从 {{arxiv}} 中，根据 arxiv_title 和 arxiv_link，总结论文内容，
  形成"AI学术论文"模块
- 从 {{GitHub}} 中，筛选最受瞩目的 5 个 AI 开源项目，提取标题和链接，
  整理为"AI开源项目"模块

输出内容总量：10条AI技术新闻 + 5篇AI学术论文 + 5个AI开源项目
```

### 步骤三：工作流编排

```
开始
  ↓
┌──────────────┬──────────────┬──────────────┐
│ RSS 插件×4   │ arXiv 插件   │ GitHub 插件  │
│ (4个媒体源)  │ (学术论文)   │ (开源项目)   │
└──────┬───────┴──────┬───────┴──────┬───────┘
       ↓              ↓              ↓
       └──────────────┴──────────────┘
                      ↓
              大模型节点（整合 + 格式化）
                      ↓
                   结束
```

### 步骤四：测试与发布

运行预览，检查简报的内容准确性、格式完整性、语言风格。不满足预期则返回调整 Prompt 或插件配置。

**发布配置**：
1. 为 Bot 配置名称、头像、描述
2. 配置开场白和预设问题（快捷指令）
3. 一键发布到微信、飞书、豆包等渠道
4. Bot 会出现在扣子商店中，也可以嵌入到 AI 应用中

### 关键技巧总结

| 技巧 | 说明 |
|------|------|
| **模板化输出** | 用 System Prompt 定义严格的输出格式模板 |
| **Emoji 标记** | 用 Emoji 做视觉分类，提升可读性 |
| **硬性数量控制** | User Prompt 中明确输出数量（10+5+5） |
| **内容过滤** | Prompt 中强调"排除广告和营销"，减少噪音 |
| **链接保留** | 要求给每条附原始链接，便于用户深挖 |
| **多渠道发布** | 完成后一键发布到飞书/微信，扩大使用范围 |

## 六种模式对比总结

| 模式 | 难度 | 核心技术栈 | 适用场景 |
|------|------|-----------|---------|
| 纯 Prompt | ⭐ | 角色设定 + 结构化 Prompt | 翻译、改写、角色扮演 |
| 知识库 | ⭐⭐ | Prompt + 知识库 RAG | 产品问答、游戏攻略 |
| 多插件 | ⭐⭐⭐ | Prompt + 多插件协同 | 旅行规划、信息查询 |
| 工作流编排 | ⭐⭐⭐⭐ | 意图识别 + 分流 + RAG | 智能客服、企业助手 |
| 多媒体生成 | ⭐⭐⭐⭐⭐ | 多节点 + 批处理 + 外部工具 | 视频/图像自动生成 |
| 多源聚合 | ⭐⭐⭐⭐ | 多插件 + 结构化输出 | 日报生成、情报监控 |

### 学习路径建议

```
纯 Prompt  →  知识库  →  多插件  →  工作流编排  →  多源聚合/多媒体生成
  (基础)       (专业)     (实时)      (复杂逻辑)        (全自动)
   1-2小时      半天        1天          2-3天            3-5天
```
