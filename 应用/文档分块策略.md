# 文档分块策略：Chunking 技术

> 分块是 RAG 中**最容易被忽视但对效果影响最大**的环节。块太大包含噪声，块太小信息不完整，分块位置不当可能把完整的段落/表格切碎。好的分块策略是高质量检索的基础。

---

## 一、为什么分块如此重要？

### 1.1 分块的影响

```
分块太小（<100 token）：
  ✗ 信息不完整，检索到的块可能缺上下文
  ✗ 语义碎片化，难以理解
  ✗ 检索结果冗余

分块太大（>2000 token）：
  ✗ 包含太多无关信息，干扰 LLM 判断
  ✗ 检索精度下降（匹配到不相关的部分）
  ✗ 浪费上下文窗口

分块位置不当：
  ✗ 把完整的段落/表格切碎
  ✗ 代码块被截断
  ✗ 语义不完整
```

### 1.2 分块的核心目标

| 目标 | 说明 |
|------|------|
| **语义完整性** | 每个块包含完整的信息单元 |
| **大小适中** | 通常 256~1024 token |
| **边界清晰** | 不要切断句子/段落 |
| **适量重叠** | 相邻块有 50~100 token 重叠 |
| **元数据保留** | 记录块的来源位置 |

## 二、基础分块策略

### 2.1 固定长度分块

```python
# 按字符/token 数切分
def fixed_length_split(text, chunk_size=512, overlap=50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end]
        chunks.append(chunk)
        start = end - overlap  # 重叠
    return chunks

# 示例
text = "这是一段很长的文本..." * 100
chunks = fixed_length_split(text, chunk_size=512, overlap=50)
```

**特点**：
- ✅ 简单可控，块大小均匀
- ❌ 可能截断句子/段落
- ❌ 不考虑语义边界

### 2.2 按分隔符分块

```python
# 按段落、换行符、标题切分
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    separators=["\n\n", "\n", "。", "，", " "],  # 按优先级尝试
    chunk_size=512,
    chunk_overlap=50
)

chunks = splitter.split_text(text)
```

**特点**：
- ✅ 保持语义完整性（不切断段落）
- ❌ 块大小不均匀
- ❌ 需要预定义分隔符

### 2.3 递归分块

```python
# LangChain 的递归字符分割器
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=50,
    length_function=len,
    separators=["\n\n", "\n", "。", "，", " ", ""]
)

# 递归逻辑：
# 1. 先按 "\n\n"（段落）切分
# 2. 如果块太大，按 "\n"（换行）切分
# 3. 如果还太大，按 "。"（句号）切分
# 4. 继续按 "，"（逗号）、" "（空格）切分
```

**特点**：
- ✅ 兼顾大小和语义
- ✅ 自动适应不同文档结构
- ❌ 实现稍复杂

## 三、高级分块策略

### 3.1 语义分块

```python
# 用 Embedding 检测语义边界
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')

def semantic_split(text, threshold=0.5):
    """根据语义相似度检测边界"""
    # 1. 按句子切分
    sentences = text.split('。')
    
    # 2. 计算相邻句子的相似度
    embeddings = model.encode(sentences)
    similarities = []
    for i in range(len(embeddings) - 1):
        sim = np.dot(embeddings[i], embeddings[i+1]) / (
            np.linalg.norm(embeddings[i]) * np.linalg.norm(embeddings[i+1])
        )
        similarities.append(sim)
    
    # 3. 相似度低于阈值的地方就是边界
    chunks = []
    current_chunk = [sentences[0]]
    for i, sim in enumerate(similarities):
        if sim < threshold:
            chunks.append('。'.join(current_chunk))
            current_chunk = [sentences[i+1]]
        else:
            current_chunk.append(sentences[i+1])
    chunks.append('。'.join(current_chunk))
    
    return chunks
```

**特点**：
- ✅ 最智能，自动检测语义边界
- ✅ 分块质量最高
- ❌ 计算开销大（需要 Embedding）
- ❌ 阈值需要调优

### 3.2 父子文档检索

```python
# 检索时用小块，返回时附带父块
class ParentChildRetriever:
    def __init__(self):
        self.parent_chunks = []  # 大块（1024 token）
        self.child_chunks = []   # 小块（256 token）
    
    def split_with_parents(self, text):
        """生成父子块"""
        # 先分成大块
        parent_chunks = split_text(text, chunk_size=1024)
        
        # 每个大块再分成小块
        for i, parent in enumerate(parent_chunks):
            child_chunks = split_text(parent, chunk_size=256)
            for child in child_chunks:
                self.parent_chunks.append(parent)
                self.child_chunks.append(child)
    
    def retrieve(self, query, top_k=3):
        """检索：用小块匹配，返回大块"""
        # 用小块检索
        child_results = search(query, self.child_chunks, top_k)
        
        # 返回对应的大块
        parent_results = [self.parent_chunks[i] for i in child_results]
        return parent_results
```

**原理**：

```
检索阶段：用 256 token 的小块去匹配（精确）
    ↓ 命中了某个小块
返回阶段：返回包含这个小块的 1024 token 大块（完整上下文）
    ↓
LLM 用大块生成（信息更完整）
```

**特点**：
- ✅ 精确匹配 + 完整上下文
- ✅ 兼顾检索精度和生成质量
- ❌ 存储开销大（需要存储两份）

### 3.3 滑动窗口分块

```python
# 固定窗口 + 重叠区域
def sliding_window_split(text, window_size=512, step=462):
    """
    window_size=512: 每个块的大小
    step=462: 步长（512-50=462，即 50 token 重叠）
    """
    chunks = []
    start = 0
    while start < len(text):
        end = start + window_size
        chunk = text[start:end]
        chunks.append(chunk)
        start += step  # 步长 < 窗口大小，产生重叠
    return chunks
```

**重叠的作用**：

```
原文：  [段落1完整内容...][段落2完整内容...][段落3完整内容...]

分块（window_size=512, overlap=50）：

Chunk 1: [段落1 的前 512 个 token .............]
Chunk 2: [段落1 末尾 50 token + 段落2 前 462 token ...]  ← 50 token 重叠
Chunk 3: [段落2 末尾 50 token + 段落3 内容 .........]

好处：边界处的信息不会丢失
```

**特点**：
- ✅ 避免边界信息丢失
- ✅ 简单有效
- ❌ 有冗余（相同内容出现在多个块中）

### 3.4 基于文档结构分块

```python
# 根据文档结构（标题、段落、表格）切分
def structure_based_split(text):
    """根据 Markdown/HTML 结构切分"""
    chunks = []
    current_chunk = []
    current_header = ""
    
    for line in text.split('\n'):
        if line.startswith('#'):  # 遇到标题
            if current_chunk:
                chunks.append({
                    'header': current_header,
                    'content': '\n'.join(current_chunk)
                })
                current_chunk = []
            current_header = line
        else:
            current_chunk.append(line)
    
    # 处理最后一块
    if current_chunk:
        chunks.append({
            'header': current_header,
            'content': '\n'.join(current_chunk)
        })
    
    return chunks
```

**特点**：
- ✅ 保持文档结构完整
- ✅ 适合结构化文档（Markdown、HTML）
- ❌ 需要解析文档结构
- ❌ 块大小不均匀

## 四、分块策略选择指南

### 4.1 场景匹配

```
通用文档（PDF、Word）：
  → 递归分块 + 滑动窗口重叠
  → chunk_size=512, overlap=50

技术文档（Markdown、代码）：
  → 基于文档结构分块
  → 保持标题和代码块完整

对话记录：
  → 按对话轮次分块
  → 每个块包含完整的问答对

表格数据：
  → 按表格行分块
  → 保留表头信息

代码文件：
  → 按函数/类分块
  → 保持代码完整性
```

### 4.2 参数选择

| 参数 | 建议值 | 说明 |
|------|--------|------|
| chunk_size | 256~1024 token | 通常 512 是好的起点 |
| overlap | 50~100 token | 通常是 chunk_size 的 10%~20% |
| separators | ["\n\n", "\n", "。", " "] | 按优先级尝试 |

### 5.2 自定义分块器

```python
class CustomChunker:
    def __init__(self, chunk_size=512, overlap=50):
        self.chunk_size = chunk_size
        self.overlap = overlap
    
    def split(self, text, metadata=None):
        """自定义分块逻辑"""
        chunks = []
        
        # 1. 先按段落切分
        paragraphs = text.split('\n\n')
        
        current_chunk = ""
        for para in paragraphs:
            # 如果当前块 + 新段落不超过大小限制
            if len(current_chunk) + len(para) <= self.chunk_size:
                current_chunk += para + '\n\n'
            else:
                # 保存当前块
                if current_chunk:
                    chunks.append({
                        'content': current_chunk,
                        'metadata': metadata
                    })
                current_chunk = para + '\n\n'
        
        # 处理最后一块
        if current_chunk:
            chunks.append({
                'content': current_chunk,
                'metadata': metadata
            })
        
        return chunks
```

## 六、面试高频问题

### Q1：分块策略怎么选？

> 常用方案是递归分块（先按段落，太大再按句子）+ 滑动窗口重叠。chunk_size 通常 256~1024 token，overlap 50~100 token。关键原则：保持语义完整性（不要切断句子/表格），块大小适中（太小信息不完整，太大包含噪声）。

### Q2：为什么需要重叠？

> 重叠避免边界信息丢失。例如，一个重要信息可能横跨两个块，如果没有重叠，这个信息会被切断，检索时可能只检索到一半。重叠确保边界处的信息在相邻块中都有完整表示。

### Q3：什么是父子文档检索？

> 检索时用小块（256 token）进行精确匹配，返回时附带包含该小块的大块（1024 token）作为完整上下文。好处是：小块检索精度高，大块提供完整信息给 LLM 生成。

### Q4：语义分块的原理是什么？

> 用 Embedding 模型计算相邻句子的语义相似度，相似度低于阈值的地方就是语义边界。例如，两个段落讨论不同主题时，相似度会下降，在这里切分。优点是分块质量高，缺点是计算开销大。

## 七、总结

**分块的核心思想**：

> 把长文档切成大小适中、语义完整的块，让检索更精准，生成更准确。

**推荐方案**：

```
默认选择：递归分块 + 滑动窗口重叠
  chunk_size=512, overlap=50

高质量需求：语义分块
  threshold=0.5（需要调优）

精确检索：父子文档检索
  child=256, parent=1024
```

**关键参数**：

| 参数 | 建议值 | 说明 |
|------|--------|------|
| chunk_size | 512 token | 平衡信息完整性和检索精度 |
| overlap | 50 token | 避免边界信息丢失 |
| separators | ["\n\n", "\n", "。"] | 按优先级尝试 |
