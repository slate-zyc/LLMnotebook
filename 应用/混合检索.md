# 混合检索：向量检索 + 关键词检索

> 单独用向量检索有个经典陷阱：用户问"GRPO"，向量检索可能返回包含"RLHF"的文档（语义相近但不精确）。混合检索结合向量检索（语义匹配）和关键词检索（精确匹配），让两者互为补充，覆盖面更广。

---

## 一、为什么需要混合检索？

### 1.1 单一向量检索的局限

```
用户查询："GRPO 算法原理"

向量检索结果（语义相似）：
  1. RLHF 详解（相似度 0.92）✓ 语义相关
  2. PPO 算法原理（相似度 0.89）✓ 语义相关
  3. GRPO 论文解读（相似度 0.85）✓ 精确匹配
  4. 强化学习基础（相似度 0.82）✓ 语义相关
  5. DPO 方法介绍（相似度 0.79）✓ 语义相关

问题：用户明确问 "GRPO"，但精确匹配的文档排在第 3 位
```

### 1.2 单一关键词检索的局限

```
用户查询："如何让模型更好地理解上下文"

关键词检索结果（精确匹配）：
  1. 上下文理解技术（包含"上下文"）
  2. 注意力机制详解（包含"理解"）
  3. 长上下文技术（包含"上下文"）

问题：可能遗漏语义相关但词汇不同的文档
  - "Transformer 架构"（不包含"上下文"但相关）
  - "Self-Attention 原理"（不包含"上下文"但相关）
```

### 1.3 混合检索的优势

| 检索方式 | 优点 | 缺点 |
|---------|------|------|
| **向量检索** | 语义匹配，处理同义词/近义词 | 可能遗漏精确术语匹配 |
| **关键词检索** | 精确匹配，处理专有名词/代码 | 无法处理同义词/语义相似 |
| **混合检索** | 两者结合，覆盖面最广 | 需要结果融合，实现稍复杂 |

## 二、混合检索原理

### 2.1 整体流程

```
用户查询："GRPO 算法原理"
    ↓
┌─────────────────────────────────────┐
│         并行检索                    │
│  ┌──────────────┐ ┌──────────────┐ │
│  │  向量检索    │ │  关键词检索  │ │
│  │  Top-10      │ │  Top-10      │ │
│  └──────────────┘ └──────────────┘ │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│         结果融合                    │
│  合并两路结果 → 去重 → 综合排序    │
└─────────────────────────────────────┘
    ↓
返回 Top-K 结果
```

### 2.2 结果融合策略

#### 策略 1：RRF（Reciprocal Rank Fusion）

```python
def reciprocal_rank_fusion(results_list, k=60):
    """
    RRF 融合算法
    results_list: 多路检索结果列表
    k: 平滑参数（通常取 60）
    """
    # 统计每个文档的 RRF 分数
    doc_scores = {}
    for results in results_list:
        for rank, doc in enumerate(results):
            doc_id = doc['id']
            if doc_id not in doc_scores:
                doc_scores[doc_id] = {'score': 0, 'doc': doc}
            # RRF 公式：1 / (k + rank)
            doc_scores[doc_id]['score'] += 1 / (k + rank + 1)
    
    # 按分数排序
    sorted_docs = sorted(
        doc_scores.values(),
        key=lambda x: x['score'],
        reverse=True
    )
    
    return [item['doc'] for item in sorted_docs]
```

**示例**：

```
向量检索结果：[A, B, C, D, E]
关键词检索结果：[C, A, F, G, B]

RRF 融合（k=60）：
A: 1/(60+1) + 1/(60+2) = 0.0164 + 0.0161 = 0.0325
B: 1/(60+2) + 1/(60+5) = 0.0161 + 0.0154 = 0.0315
C: 1/(60+3) + 1/(60+1) = 0.0159 + 0.0164 = 0.0323
D: 1/(60+4) = 0.0156
E: 1/(60+5) = 0.0154
F: 1/(60+3) = 0.0159
G: 1/(60+4) = 0.0156

融合排序：[A, C, B, D, F, G, E]
```

#### 策略 2：加权分数融合

```python
def weighted_fusion(vector_results, keyword_results, 
                     vector_weight=0.7, keyword_weight=0.3):
    """
    加权分数融合
    """
    doc_scores = {}
    
    # 归一化向量检索分数（假设已归一化到 0-1）
    for doc in vector_results:
        doc_id = doc['id']
        score = doc['score'] * vector_weight
        doc_scores[doc_id] = {'score': score, 'doc': doc}
    
    # 归一化关键词检索分数（如 BM25 分数）
    max_keyword_score = max([doc['score'] for doc in keyword_results])
    for doc in keyword_results:
        doc_id = doc['id']
        # 归一化到 0-1
        normalized_score = doc['score'] / max_keyword_score
        score = normalized_score * keyword_weight
        
        if doc_id in doc_scores:
            doc_scores[doc_id]['score'] += score
        else:
            doc_scores[doc_id] = {'score': score, 'doc': doc}
    
    # 按分数排序
    sorted_docs = sorted(
        doc_scores.values(),
        key=lambda x: x['score'],
        reverse=True
    )
    
    return [item['doc'] for item in sorted_docs]
```

#### 策略 3：排名融合（Rank Fusion）

```python
def rank_fusion(vector_results, keyword_results):
    """
    简单的排名融合
    """
    doc_ranks = {}
    
    # 记录每个文档在两路结果中的排名
    for rank, doc in enumerate(vector_results):
        doc_id = doc['id']
        doc_ranks[doc_id] = {'ranks': [rank + 1], 'doc': doc}
    
    for rank, doc in enumerate(keyword_results):
        doc_id = doc['id']
        if doc_id in doc_ranks:
            doc_ranks[doc_id]['ranks'].append(rank + 1)
        else:
            doc_ranks[doc_id] = {'ranks': [rank + 1], 'doc': doc}
    
    # 计算平均排名
    for doc_id in doc_ranks:
        ranks = doc_ranks[doc_id]['ranks']
        doc_ranks[doc_id]['avg_rank'] = sum(ranks) / len(ranks)
    
    # 按平均排名排序
    sorted_docs = sorted(
        doc_ranks.values(),
        key=lambda x: x['avg_rank']
    )
    
    return [item['doc'] for item in sorted_docs]
```

## 三、关键词检索算法

### 3.1 BM25

BM25 是最常用的关键词检索算法：

```python
import math
from collections import Counter

class BM25:
    def __init__(self, k1=1.5, b=0.75):
        self.k1 = k1  # 词频饱和参数
        self.b = b    # 文档长度归一化参数
        self.doc_freqs = {}  # 词在多少文档中出现
        self.doc_lens = []   # 每个文档的长度
        self.avg_doc_len = 0
        self.corpus_size = 0
    
    def fit(self, documents):
        """构建索引"""
        self.corpus_size = len(documents)
        self.doc_lens = [len(doc) for doc in documents]
        self.avg_doc_len = sum(self.doc_lens) / self.corpus_size
        
        # 统计文档频率
        for doc in documents:
            words = set(doc)
            for word in words:
                self.doc_freqs[word] = self.doc_freqs.get(word, 0) + 1
    
    def score(self, query, doc):
        """计算查询和文档的 BM25 分数"""
        score = 0
        doc_len = len(doc)
        word_counts = Counter(doc)
        
        for word in query:
            if word not in word_counts:
                continue
            
            # 词频
            tf = word_counts[word]
            
            # 逆文档频率
            df = self.doc_freqs.get(word, 0)
            idf = math.log((self.corpus_size - df + 0.5) / (df + 0.5) + 1)
            
            # BM25 公式
            tf_component = (tf * (self.k1 + 1)) / (
                tf + self.k1 * (1 - self.b + self.b * doc_len / self.avg_doc_len)
            )
            
            score += idf * tf_component
        
        return score
```

**BM25 公式**：

```
BM25(q, d) = Σ IDF(qi) × (tf(qi, d) × (k1 + 1)) / (tf(qi, d) + k1 × (1 - b + b × |d| / avgdl))

其中：
- qi: 查询中的词
- tf(qi, d): 词 qi 在文档 d 中的词频
- |d|: 文档长度
- avgdl: 平均文档长度
- k1: 词频饱和参数（通常 1.5~2.0）
- b: 文档长度归一化参数（通常 0.75）
```

### 3.2 其他关键词检索算法

| 算法 | 特点 | 适用场景 |
|------|------|---------|
| **TF-IDF** | 简单，基于词频和逆文档频率 | 基础场景 |
| **BM25** | TF-IDF 的改进，效果更好 | 最常用 |
| **Lucene** | 工业级实现，支持多种特性 | 生产环境 |
| **Elasticsearch** | 基于 Lucene，功能全面 | 大规模检索 |

## 五、混合检索最佳实践

### 5.1 权重选择

```
语义匹配更重要（如问答系统）：
  vector_weight = 0.7~0.8
  keyword_weight = 0.2~0.3

精确匹配更重要（如代码搜索）：
  vector_weight = 0.3~0.4
  keyword_weight = 0.6~0.7

平衡场景：
  vector_weight = 0.5~0.6
  keyword_weight = 0.4~0.5
```

**混合检索的精髓**：向量检索负责"语义理解"（找到意思相似的文档），关键词检索负责"精确匹配"（找到包含特定术语的文档）。两者结合后，即使用户用不同的词汇表达相同的意思，或者用户精确搜索某个术语，都能找到相关文档。

## 六、面试高频问题

### Q1：什么是混合检索？为什么需要它？

> 混合检索结合向量检索（语义匹配）和关键词检索（精确匹配）。单独用向量检索可能遗漏精确术语匹配（如搜索 "GRPO" 可能返回 "RLHF" 的文档），单独用关键词检索无法处理同义词和语义相似。两者结合后取并集重排，覆盖面更广。

### Q2：RRF 算法的原理是什么？

> RRF（Reciprocal Rank Fusion）是一种结果融合算法。它将每路检索结果中每个文档的排名转换为分数：分数 = 1 / (k + rank)，其中 k 是平滑参数（通常 60）。然后将多路结果中同一文档的分数相加，按总分排序。

### Q3：混合检索的权重怎么选？

> 权重选择取决于应用场景：
> - 语义匹配更重要（如问答系统）：向量权重 0.7~0.8
> - 精确匹配更重要（如代码搜索）：向量权重 0.3~0.4
> - 平衡场景：向量权重 0.5~0.6
> 
> 通常需要在实际数据上测试调优。

### Q4：BM25 和向量检索有什么区别？

> - **BM25**：基于词频和逆文档频率，精确匹配关键词，无法处理同义词
> - **向量检索**：基于语义相似度，可以处理同义词，但可能遗漏精确匹配
> 
> 两者互补，混合使用效果最好。

## 七、总结

**混合检索的核心思想**：

> 向量检索负责语义理解，关键词检索负责精确匹配，两者结合覆盖面最广。

**推荐方案**：

```
默认选择：向量检索 + BM25 + RRF 融合
  向量权重 0.7，关键词权重 0.3

精确匹配场景：增加关键词权重
  向量权重 0.4，关键词权重 0.6

语义匹配场景：增加向量权重
  向量权重 0.8，关键词权重 0.2
```

**关键参数**：

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 向量权重 | 0.5~0.8 | 根据场景调整 |
| 关键词权重 | 0.2~0.5 | 根据场景调整 |
| RRF.k | 60 | 平滑参数 |
| BM25.k1 | 1.5~2.0 | 词频饱和参数 |
| BM25.b | 0.75 | 文档长度归一化参数 |
