# 偏好数据构建

> 一条偏好样本回答的是：**在同一个问题、相同的上下文和约束下，为什么回答 A 比回答 B 更合适？** 能说清这个理由，才知道数据在教模型什么。

## 一、偏好数据长什么样？

[[SFT：监督微调|SFT]] 常用「问题 + 示范回答」。偏好学习再提供一个候选，让模型看到**同一题目内的质量差异**。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `prompt` | 两个回答共享的输入。包括系统要求、对话历史或给定材料 | 只按材料回答。材料：课程周五 18:00 停止提交。问：周五几点截止？ |
| `chosen` | 按标注准则更合适的回答 | 周五 18:00。 |
| `rejected` | 同一输入下相对较差的回答 | 周五 20:00。 |

这对样本教的是“从给定材料提取正确的截止时间”。两个回答长度和格式接近，关键差异只有一个时间。如果差回答是一段完全不相干的话，模型很容易分出胜负，但学到的可能只是“要回答问题”，没学到“别改动材料里的数字”。

`chosen` 表示**这一次比较的胜者**，不保证它能作为高质量示范。两个回答都漏了关键信息时，可以把这对留给分析，另外写出合格候选再参与标注。

- **训练[[奖励模型]]**：输入问题和单个回答，输出分数。训练时让模型给 `chosen` 的分数高于 `rejected`，之后可用这个分数给 [[PPO]] 生成的回答提供奖励。InstructGPT 是从人工排序构造这类信号的一个实例。[InstructGPT 论文](https://arxiv.org/abs/2203.02155)
- **训练 [[DPO]]**：在固定的偏好对上更新策略模型。DPO 相对参考模型优化两个回答的概率比，无需额外训练一个独立的奖励模型。[DPO 论文](https://arxiv.org/abs/2305.18290)
- **训练 [[GRPO]]**：典型的在线流程从 prompt 采样一组新回答，再用规则或奖励函数打分。离线准备的偏好对可以用于训练奖励模型或离线评估，训练器使用的数据形式要按实际流程确认。[TRL 数据集格式](https://huggingface.co/docs/trl/main/en/dataset_formats#which-dataset-type-to-use)

## 二、怎么构造一批可靠的偏好对？

### 2.1 先选问题，再生成候选

按实际用途采样问题，至少覆盖**常见任务、容易答错的边界和信息不足的情况**。例如课程问答可以同时收录直接查找、跨段核对、材料未给答案三类问题。使用真实记录前先检查使用权限，并删除身份信息和私密内容。

同一个 `prompt` 可以让当前模型多采样几次，也可以引入其他模型的回答或人工改写。混合候选来源，避免形成“模型甲的输出永远是正例、模型乙永远是负例”的捷径。先观察当前模型常犯的错，再补看起来合理但关键细节错误的**难负例**。

### 2.2 把标注标准写成能执行的规则

先检查事实和约束，再比较完整性和表达。课程问答可以从下面三条起步：

| 判断项 | 怎么标 |
| --- | --- |
| 材料可核对 | 优先选事实与材料一致的回答，指出可核对的区别。例如时间写错或把建议说成硬性规定。 |
| 材料未提供答案 | 优先选明确指出缺少哪条信息的回答。事实已经给出时，泛泛回避也算没有完成任务。 |
| 两个答案都满足要求 | 表达差异没有实质影响就标平局。问题不明确或材料矛盾时标“无法判断”。 |

客观任务优先用可复核的依据，例如对照给定材料、解析 JSON 格式或运行单元测试。开放问题可以由人按统一标准比较，也可以先用模型打标，再人工复核模型不一致的样本。比较时隐藏候选模型名并打乱 A/B 的顺序。用模型做裁判时，可以对一批样本交换 A/B 重判，按**回答身份**比对胜者，发现顺序会改变结论就送人工复核。还要抽查裁判是否把篇幅或自信语气当作质量指标。[LLM-as-a-Judge 研究](https://arxiv.org/abs/2306.05685)

训练数据保存胜负顺序，审核表另外保存 `prompt_id`、来源、标注理由和分歧记录。给审阅者看的理由别拼进模型训练的回答字段。普通二元偏好训练可以先过滤平局、无法判断和标注冲突，冲突样本留待仲裁。

### 2.3 排序转配对时，别让一题撑大样本量

如果同一问题的候选排成 `A > B > C`，可以得到 `A > B`、`A > C` 和 `B > C`。这三条共享一个问题和几个回答，有相关性。候选很多的题若全部展开，在训练中会占更大权重。起步时可以给每题设配对上限，保留一些差距明显的对，以及一些差距小但判据清楚的对。分不清胜负的相邻回答不用硬排。

## 三、把标注表转成训练数据

### 3.1 最小 JSONL 格式

这里用显式 `prompt` 的文本格式。每行是一条 JSON 记录。对话任务也可用 `role` 和 `content` 的消息列表，显式的 `prompt` 放完整的共同前缀，`chosen`、`rejected` 各放候选回复。导入训练器前检查它所需的格式，并用实际模型的 chat template 对两边做相同处理。[TRL 偏好数据格式](https://huggingface.co/docs/trl/main/en/dataset_formats#preference)

```jsonl
{"prompt":"只按材料回答。材料：课程周五 18:00 停止提交。问：周五几点截止？","chosen":"周五 18:00。","rejected":"周五 20:00。"}
```

### 3.2 一个只用 Python 标准库的例子

原始标注用 `winner` 记录胜者。下面保留 `A` 和 `B` 的明确胜负，跳过平局、缺失文本和相同回答。输出可直接用作 JSONL 的一行。例子解决的是**格式转换**，文本正确性仍靠标注环节保证。

```python
import json

rows = [
    {
        "prompt": "只按材料回答。材料：课程周五 18:00 停止提交。问：周五几点截止？",
        "a": "周五 18:00。",
        "b": "周五 20:00。",
        "winner": "A",
    }
]


def to_pair(row):
    prompt = row.get("prompt") or ""
    a = row.get("a") or ""
    b = row.get("b") or ""
    winner = row.get("winner")
    if winner not in {"A", "B"}:
        return None
    if not prompt.strip() or not a.strip() or not b.strip() or a.strip() == b.strip():
        return None

    chosen, rejected = (a, b) if winner == "A" else (b, a)
    return {"prompt": prompt, "chosen": chosen, "rejected": rejected}


for row in rows:
    pair = to_pair(row)
    if pair is not None:
        print(json.dumps(pair, ensure_ascii=False))
```

## 四、去重、划分与质检

1. **按问题分组，再划分训练、验证与测试集。** 同一问题的所有配对只能进入一个集合。问题改写、同一个模板的轻微变形，以及共享材料且检验同一事实的样本也应放在同一组。若应用要求推广到新文档，可直接按文档分组。逐行随机切分会让模型在验证集再次见到训练中的问题。
2. **去掉重复和冲突。** 检查完全重复的对、颠倒后标签冲突的对，以及清洗后两个答案变成一样的记录。长文本再用实际模型的 tokenizer 检查截断，防止证据、答案差异或格式约束在截断后消失。
3. **按任务和来源抽检。** 记录独立问题数、每题配对数、冲突或平局比例，以及正负答案的长度差。如果仅凭“哪个更长”就能猜中大多数标签，复查标注准则和候选来源。按类别挑几条失败案例，通常比只看总条数更能指出该往哪种任务补数据。

## 五、常见问题

### Q1：能把另一道题的回答当作 rejected 吗？

通常不这样做。DPO 和成对奖励模型比较的是同一输入下的两种回复。跨题拼接会把任务差异混进标签，而且许多错配只教模型辨认离题。更好的负例是当前模型在**原问题**上会犯的错误。

### Q2：正例和负例的长度必须相等吗？

不用人为凑到一样长。用户要求详解时，更完整的回答确实可能更长。要检查的是长度能否替代事实正确、约束遵循等真正的偏好标准。可以抽查短答案获胜的样本，并设计少量长度接近、只差关键事实的对。

### Q3：有 1 万条配对就等于覆盖了 1 万个问题吗？

不等于。若配对集中在少数问题或近重复模板，新增行数主要来自重复比较。报告数据规模时同时给出**独立问题数**和**配对数**，解释两者差多少。

### Q4：模型裁判和人工判断不一致，怎么处理？

先回看标注标准和参考材料。交换 A/B 后裁决翻转的样本单独复核。若分歧反映不同用户的真实需求，可以给这些问题加上明确的使用场景或风格约束后重新标注。暂时说不清原因的样本先留在审核表。

## 六、速查表

| 检查点 | 起步做法 |
| --- | --- |
| 可比 | 同一问题、同一上下文和约束 |
| 有判据 | 标注者能说清胜出原因。允许平局和无法判断。 |
| 能复查 | 保存来源和理由。抽查长度、顺序和候选来源偏差。 |
| 无泄漏 | 按独立问题或文档分组切分，检查重复和截断。 |

记忆顺序：**同题出答案 → 按标准判胜负 → 按问题划分 → 按类别抽检**。下一步可看[[奖励模型]]如何把偏好变成分数，或看 [[DPO]] 如何直接用偏好对训练策略。
