# 分布式训练

> Scaling Laws 告诉你模型要大、数据要多，但**单张显卡放不下、训练太慢怎么办？** 分布式训练就是把训练任务拆分到多张显卡甚至多台机器上并行执行。这是大模型训练的工程基础。

---

## 一、为什么需要分布式训练

### 1.1 显存瓶颈

| 模型规模 | 参数量 | FP16 显存占用 | 训练显存（含优化器） |
|---------|--------|-------------|-------------------|
| GPT-2 | 1.5B | 3 GB | ~12 GB |
| LLaMA 7B | 7B | 14 GB | ~56 GB |
| LLaMA 70B | 70B | 140 GB | ~560 GB |
| GPT-4 级别 | ~1.8T | 3.6 TB | ~14 TB |

**单张 A100 80GB 显存**，连 LLaMA 7B 的训练都放不下（需要优化器状态、梯度等），更别说 70B。

### 1.2 训练速度瓶颈

```
单卡训练 70B 模型：
- 显存不够，需要用 offload（把部分数据放内存）
- 一次前向+反向传播需要几分钟
- 训练 1T tokens 可能需要几年

多卡并行：
- 8 卡 A100：几周到几个月
- 64 卡 A100：几天到几周
- 数千卡 H100：几天完成
```

## 二、并行策略概览

```
┌─────────────────────────────────────────────────────────────┐
│                      分布式训练策略                           │
├─────────────────┬─────────────────┬─────────────────────────┤
│   数据并行       │   模型并行       │   流水线并行             │
│ (Data Parallel) │(Model Parallel) │ (Pipeline Parallel)     │
├─────────────────┼─────────────────┼─────────────────────────┤
│ 每张卡完整模型   │ 模型拆分到多卡   │ 模型按层拆分             │
│ 只拆分数据       │ 每卡只算一部分   │ 不同卡算不同层           │
└─────────────────┴─────────────────┴─────────────────────────┘
```

## 三、数据并行（Data Parallelism）

### 3.1 基本原理

```
核心思想：每张卡都有完整模型，但处理不同的数据

GPU 0: 完整模型 → 处理 batch 0 → 梯度 0
GPU 1: 完整模型 → 处理 batch 1 → 梯度 1
GPU 2: 完整模型 → 处理 batch 2 → 梯度 2
GPU 3: 完整模型 → 处理 batch 3 → 梯度 3
                ↓
        AllReduce 梯度同步
                ↓
        每张卡更新自己的模型
```

### 3.2 PyTorch DDP（DistributedDataParallel）

```python
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

# 初始化进程组
dist.init_process_group(backend='nccl')

# 创建模型
model = MyModel().to(rank)
model = DDP(model, device_ids=[rank])

# 训练循环（每张卡自动处理不同的数据）
for batch in dataloader:
    loss = model(batch)
    loss.backward()
    # DDP 自动同步梯度（AllReduce）
    optimizer.step()
```

### 3.3 梯度同步：AllReduce

**AllReduce 操作**：把所有卡的梯度求和/求平均，然后分发给每张卡。

```
GPU 0 梯度: [0.1, 0.2, 0.3]
GPU 1 梯度: [0.4, 0.1, 0.2]
GPU 2 梯度: [0.2, 0.3, 0.1]
GPU 3 梯度: [0.3, 0.4, 0.5]
                ↓
        AllReduce（求平均）
                ↓
所有卡的梯度: [0.25, 0.25, 0.275]
```

**通信优化：Ring-AllReduce**：

```
传统 AllReduce：每张卡都要和所有其他卡通信 → O(N²) 通信量
Ring-AllReduce：每张卡只和相邻两张卡通信 → O(N) 通信量

GPU 0 ←→ GPU 1 ←→ GPU 2 ←→ GPU 3
  ↘                              ↗
    ←←←←←←←←←←←←←←←←←←←←←←←←
```

### 3.4 数据并行的局限

| 问题 | 说明 |
|------|------|
| **显存冗余** | 每张卡都存完整模型，N 张卡需要 N 倍显存 |
| **通信开销** | 每个 step 都要同步梯度，卡多时通信成为瓶颈 |
| **模型放不下** | 如果单卡放不下完整模型，数据并行无法使用 |

## 四、ZeRO（Zero Redundancy Optimizer）

### 4.1 解决数据并行的显存问题

DeepSpeed 的 ZeRO 优化是数据并行的进化版，核心思想：**把优化器状态、梯度、模型参数分片存储到不同卡上**。

### 4.2 ZeRO 的三个阶段

| 阶段 | 分片内容 | 显存节省 | 通信开销 |
|------|---------|---------|---------|
| **ZeRO-1** | 优化器状态 | 4x | 无额外开销 |
| **ZeRO-2** | + 梯度 | 8x | 无额外开销 |
| **ZeRO-3** | + 模型参数 | $N_d$ 倍 | 增加 1.5x |

其中 $N_d$ 是 GPU 数量。

### 4.3 显存占用分析

**训练时每张卡的显存占用**（混合精度）：

```
模型参数（FP16）:           2N bytes
梯度（FP16）:               2N bytes
优化器状态（FP32）:
  - 参数副本:               4N bytes
  - 一阶动量:               4N bytes
  - 二阶动量:               4N bytes
                           ────────
总计:                       16N bytes（N 是参数量）

7B 模型 → 112 GB（单卡放不下！）
```

**ZeRO 各阶段的显存占用**：

| 阶段 | 每卡显存（7B 模型） | 8 卡时总显存 |
|------|-------------------|-------------|
| 无优化 | 112 GB | 896 GB |
| ZeRO-1 | 28 GB + 14 GB = 42 GB | 336 GB |
| ZeRO-2 | 14 GB + 14 GB = 28 GB | 224 GB |
| ZeRO-3 | ~14 GB + 14 GB ≈ 28 GB | 224 GB |

### 4.4 ZeRO 的实现

```python
from deepspeed import DeepSpeed

# DeepSpeed 配置
ds_config = {
    "train_batch_size": 32,
    "gradient_accumulation_steps": 4,
    "fp16": {"enabled": True},
    "zero_optimization": {
        "stage": 2,  # ZeRO-2
        "allgather_partitions": True,
        "allgather_bucket_size": 5e8,
        "overlap_comm": True,
        "reduce_scatter": True,
        "reduce_bucket_size": 5e8,
        "contiguous_gradients": True
    }
}

model, optimizer, _, _ = DeepSpeed.initialize(
    model=model,
    config=ds_config
)
```

`★ Insight ─────────────────────────────────────`
**ZeRO-3 vs 模型并行**：ZeRO-3 把参数分片到不同卡上，每张卡只存部分参数，但计算时需要临时收集完整参数。这和张量并行（Tensor Parallelism）不同——张量并行是把计算也拆分了。ZeRO-3 的优点是兼容性好（不需要改模型代码），缺点是通信开销大。
`─────────────────────────────────────────────────`

## 五、张量并行（Tensor Parallelism）

### 5.1 基本原理

**核心思想**：把单个层的计算拆分到多张卡上。

**以矩阵乘法为例**：

```
原始计算: Y = XA（A 是权重矩阵）

张量并行（按列切分）:
  GPU 0: Y₀ = X · A₀（A 的前半部分）
  GPU 1: Y₁ = X · A₁（A 的后半部分）
  
  结果拼接: Y = [Y₀; Y₁]
```

### 5.2 Megatron-LM 的实现

Megatron-LM（NVIDIA）对 Transformer 的张量并行：

```
┌─────────────────────────────────────────────────────┐
│                 单个 Transformer 层                   │
├─────────────────────────────────────────────────────┤
│  Self-Attention:                                     │
│    Q, K, V 投影: 按列切分 → 每卡只算部分头            │
│    输出投影: 按行切分 → 每卡只算部分输出               │
│                                                     │
│  FFN:                                                │
│    W₁ 矩阵: 按列切分 → 每卡只算部分神经元             │
│    W₂ 矩阵: 按行切分 → 每卡只算部分输出               │
└─────────────────────────────────────────────────────┘
```

**具体流程**：

```
输入 X (shape: [batch, seq, hidden])

GPU 0:                      GPU 1:
  Q₀ = X · W_Q₀              Q₁ = X · W_Q₁
  K₀ = X · W_K₀              K₁ = X · W_K₁
  V₀ = X · W_V₀              V₁ = X · W_V₁
  ↓                           ↓
  Attention(Q₀,K₀,V₀)        Attention(Q₁,K₁,V₁)
  ↓                           ↓
  Y₀ = head₀ · W_O₀          Y₁ = head₁ · W_O₁
  ↓                           ↓
        AllReduce（求和）
              ↓
        最终输出 Y
```

### 5.3 张量并行的适用场景

| 优点 | 缺点 |
|------|------|
| 通信只在特定层发生 | 需要修改模型代码 |
| 通信量相对可控 | 对模型结构有要求 |
| 适合同一节点内的多卡 | 跨节点通信开销大 |

**实践建议**：张量并行通常用于**同一台机器内的 4-8 张卡**，因为需要高速互联（NVLink）。

## 六、流水线并行（Pipeline Parallelism）

### 6.1 基本原理

**核心思想**：把模型按层切分，不同卡负责不同的层。

```
原始模型（24 层）:

GPU 0: Layer 0-5     ←→    GPU 1: Layer 6-11
   ↓                              ↓
GPU 3: Layer 18-23   ←→    GPU 2: Layer 12-17
```

### 6.2 流水线调度

**朴素实现的问题**：

```
时间 →
GPU 0: [前向 Layer 0-5] ....................... [反向 Layer 0-5]
GPU 1:              [前向 Layer 6-11] .............. [反向 Layer 6-11]
GPU 2:                           [前向 Layer 12-17] ......... [反向 ...]
GPU 3:                                        [前向 Layer 18-23] ...

问题：大量空闲时间（气泡，Bubble）
```

**GPipe 调度**（微批次）：

```
核心思想：把一个 batch 拆成多个 micro-batch，形成流水线

时间 →
GPU 0: [F₁][F₂][F₃][F₄] ... [B₄][B₃][B₂][B₁]
GPU 1:     [F₁][F₂][F₃][F₄] ... [B₄][B₃][B₂][B₁]
GPU 2:         [F₁][F₂][F₃][F₄] ... [B₄][B₃][B₂][B₁]
GPU 3:             [F₁][F₂][F₃][F₄] ... [B₄][B₃][B₂][B₁]

F = Forward, B = Backward, 数字 = micro-batch 编号
```

### 6.3 气泡率分析

```
气泡率 = 空闲时间 / 总时间

假设 P 个 pipeline stage，M 个 micro-batch：
气泡率 ≈ (P-1) / (M + P-1)

要气泡率 < 5%：
  需要 M > 19 × P（如果 P=4，需要 M > 76）
```

### 6.4 1F1B 调度（One Forward One Backward）

```
核心思想：尽早开始反向传播，释放显存

GPU 0: F₁ F₂ F₃ F₄ B₁ F₅ B₂ F₆ B₃ ...
GPU 1:    F₁ F₂ F₃ B₁ F₄ B₂ F₅ B₃ ...

优点：显存占用更可控，不需要存所有 micro-batch 的激活
```

### 6.5 Interleaved 1F1B（Megatron-LM）

```
核心思想：每个 GPU 负责多个不连续的层（虚拟流水线阶段）

GPU 0: Layer 0-2, Layer 12-14（两个不连续的阶段）
GPU 1: Layer 3-5, Layer 15-17
GPU 2: Layer 6-8, Layer 18-20
GPU 3: Layer 9-11, Layer 21-23

优点：气泡率更低
缺点：通信量增加
```

## 七、3D 并行

### 7.1 组合策略

大模型训练通常组合使用多种并行策略：

```
3D 并行 = 数据并行 × 张量并行 × 流水线并行

例如 64 卡训练：
- 数据并行: 4 组
- 张量并行: 每组 4 卡（同一节点）
- 流水线并行: 跨 4 个节点

节点 0 (4 GPU): [TP=4, PP=stage 0]
节点 1 (4 GPU): [TP=4, PP=stage 1]
节点 2 (4 GPU): [TP=4, PP=stage 2]
节点 3 (4 GPU): [TP=4, PP=stage 3]
  × 4 组数据并行
```

### 7.2 并行策略选择指南

| 场景 | 推荐策略 |
|------|---------|
| 模型小（<10B），卡多 | 纯数据并行 |
| 模型中等（10B-70B），同节点 | 张量并行 + 数据并行 |
| 模型大（70B+），跨节点 | 3D 并行 |
| 显存紧张 | ZeRO-3 或 流水线并行 |

### 7.3 通信拓扑优化

```
原则：把通信量大的操作放在高速互联的 GPU 之间

通信量排序：
张量并行 > 流水线并行 > 数据并行

因此：
- 张量并行：同一节点内（NVLink，600+ GB/s）
- 流水线并行：跨节点（InfiniBand，100-400 Gb/s）
- 数据并行：跨节点（梯度同步可以延迟/重叠）
```

## 八、面试高频问题

### Q1：数据并行和模型并行有什么区别？

> **数据并行**：每张卡都有完整模型，但处理不同的数据 batch，训练后同步梯度。优点是实现简单，缺点是显存冗余。**模型并行**：把模型拆分到不同卡上，每张卡只负责部分计算。包括张量并行（按矩阵维度切分）和流水线并行（按层切分）。优点是能训练超大模型，缺点是需要精心设计通信。

### Q2：ZeRO 是什么？它的三个阶段有什么区别？

> ZeRO（Zero Redundancy Optimizer）是 DeepSpeed 的显存优化技术。**ZeRO-1** 分片优化器状态，显存节省 4x；**ZeRO-2** 额外分片梯度，节省 8x；**ZeRO-3** 额外分片模型参数，节省 $N_d$ 倍（$N_d$ 是 GPU 数）。ZeRO-1/2 无额外通信开销，ZeRO-3 需要临时收集参数，通信量增加约 1.5x。

### Q3：什么是张量并行？为什么说它适合同一节点内的多卡？

> 张量并行把单层的计算（如矩阵乘法）按维度切分到多张卡上，每张卡只计算部分结果，最后 AllReduce 合并。它适合同节点多卡是因为：(1) 每层都需要通信，通信频率高；(2) 需要低延迟高带宽的互联，NVLink（600+ GB/s）远优于跨节点的 InfiniBand（~50 GB/s）。

### Q4：流水线并行的"气泡"是什么？如何减少？

> 气泡是指流水线中 GPU 空闲等待的时间。因为前向传播是分阶段的，后一阶段必须等前一阶段完成才能开始。减少气泡的方法：(1) 增加 micro-batch 数量 M（气泡率 ≈ (P-1)/(M+P-1)）；(2) 使用 1F1B 调度尽早开始反向传播；(3) 使用 Interleaved 调度让每个 GPU 负责多个不连续的层。

### Q5：3D 并行是什么？如何选择并行策略？

> 3D 并行是数据并行、张量并行、流水线并行的组合。选择策略：(1) 模型小、卡多 → 纯数据并行；(2) 模型中等、同节点 → 张量并行 + 数据并行；(3) 模型大、跨节点 → 3D 并行。关键是把通信量大的操作（张量并行）放在高速互联（NVLink）的 GPU 之间。

### Q6：训练 70B 模型，有 64 张 A100 80GB，如何设计并行策略？

> 推荐方案：**张量并行 4（同节点）× 流水线并行 4（跨 4 节点）× 数据并行 4**。每个节点 4 卡做张量并行（NVLink 高速通信），4 个节点做流水线并行（每节点 6 层），4 组数据并行（梯度同步可以延迟）。ZeRO-1 可进一步节省显存。预计训练时间：取决于 batch size 和数据量，通常几周到几个月。

## 九、总结

| 策略 | 原理 | 适用场景 | 通信特点 |
|------|------|---------|---------|
| 数据并行 | 每卡完整模型，拆分数据 | 模型能放下 | 每步 AllReduce |
| ZeRO | 分片优化器/梯度/参数 | 显存紧张 | ZeRO-3 额外通信 |
| 张量并行 | 按矩阵维度切分 | 同节点多卡 | 每层通信 |
| 流水线并行 | 按层切分 | 跨节点 | 阶段间通信 |
| 3D 并行 | 组合以上策略 | 超大模型 | 综合 |

**一句话记忆**：

> 数据并行是"人多力量大"（多卡处理不同数据），模型并行是"分工合作"（多卡处理模型的不同部分），ZeRO 是"共享储物柜"（显存分片），3D 并行是"把它们组合起来"。
