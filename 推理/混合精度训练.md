# 混合精度训练

> 分布式训练解决了"模型太大、单卡放不下"的问题，但还有一个问题：**计算太慢、显存还是不够用**。混合精度训练通过使用低精度数值（FP16/BF16）来加速计算、节省显存，是大模型训练的标配技术。

---

## 一、什么是混合精度训练

### 1.1 核心思想

**混合精度**：在训练中同时使用**高精度（FP32）**和**低精度（FP16/BF16）**数值，兼顾训练稳定性和效率。

```
不是"全用低精度"，而是"该用低精度用低精度，该用高精度用高精度"

模型参数：FP16/BF16（参与前向和反向计算）
优化器状态：FP32（需要高精度累积）
模型参数副本：FP32（用于更新，避免精度损失）
```

### 1.2 为什么不用纯 FP32？

```
纯 FP32 训练：
  - 显存占用大（每个参数 4 bytes）
  - 计算慢（GPU 的 FP32 单元利用率低）
  - 但训练稳定，不会出现数值问题

纯 FP16 训练：
  - 显存占用小（每个参数 2 bytes）
  - 计算快（GPU 有专门的 Tensor Core 加速）
  - 但容易出现数值问题（溢出、下溢）

混合精度：
  - 用 FP16/BF16 做计算（快 + 省显存）
  - 用 FP32 做更新（稳定 + 精度高）
  - 两全其美
```

## 二、数值格式对比

### 2.1 FP32（单精度浮点）

```
符号位: 1 bit
指数位: 8 bits
尾数位: 23 bits

范围: ±3.4 × 10³⁸
精度: 约 7 位有效数字
占用: 4 bytes
```

### 2.2 FP16（半精度浮点）

```
符号位: 1 bit
指数位: 5 bits
尾数位: 10 bits

范围: ±6.55 × 10⁴
精度: 约 3.3 位有效数字
占用: 2 bytes
```

**问题**：

| 问题 | 表现 | 影响 |
|------|------|------|
| **溢出（Overflow）** | 值 > 6.55 × 10⁴ | 变成 `inf`，训练崩溃 |
| **下溢（Underflow）** | 值 < 2⁻²⁴ ≈ 6 × 10⁻⁸ | 变成 0，梯度消失 |
| **精度不足** | 大数 + 小数 | 小数被"吃掉" |

### 2.3 BF16（Brain Floating Point）

```
符号位: 1 bit
指数位: 8 bits（和 FP32 相同！）
尾数位: 7 bits

范围: ±3.4 × 10³⁸（和 FP33 一样！）
精度: 约 2.4 位有效数字（比 FP16 低）
占用: 2 bytes
```

**BF16 vs FP16**：

| 特性 | FP16 | BF16 |
|------|------|------|
| 范围 | ±6.55 × 10⁴ | ±3.4 × 10³⁸ |
| 精度 | 3.3 位有效数字 | 2.4 位有效数字 |
| 溢出风险 | 高 | 低（范围大） |
| 下溢风险 | 高 | 低（范围大） |
| 精度损失 | 较小 | 较大 |

`★ Insight ─────────────────────────────────────`
**BF16 是大模型训练的首选**：虽然精度比 FP16 低，但范围和 FP32 相同，几乎不会溢出/下溢。训练时主要关心的是"范围够不够"而不是"精度够不够"，因为梯度的量级变化很大。NVIDIA A100/H100 原生支持 BF16。
`─────────────────────────────────────────────────`

### 2.4 FP8（未来趋势）

```
两种格式：
- E4M3: 4 bit 指数 + 3 bit 尾数（用于前向传播）
- E5M2: 5 bit 指数 + 2 bit 尾数（用于反向传播）

占用: 1 byte
优势: 显存减半，速度翻倍
挑战: 精度更低，需要更精细的 scaling 策略
```

H100 GPU 原生支持 FP8，是下一代训练格式。

## 三、混合精度训练的实现

### 3.1 核心组件

```
混合精度训练需要三个关键组件：

1. FP16/BF16 主权重（用于前向和反向计算）
2. FP32 主权重副本（用于参数更新）
3. 动态损失缩放（解决 FP16 下溢问题）
```

### 3.2 训练流程

```python
# 伪代码：混合精度训练

# 初始化
master_weights_fp32 = model.parameters()  # FP32 副本
model = model.half()  # 转换为 FP16/BF16

for batch in dataloader:
    # 1. 前向传播（FP16/BF16）
    with autocast():
        output = model(batch)
        loss = criterion(output, target)
    
    # 2. 反向传播（FP16/BF16）
    loss.backward()  # 梯度是 FP16/BF16
    
    # 3. 梯度缩放（FP16 专用）
    scaler.scale(loss).backward()
    
    # 4. 参数更新
    scaler.unscale_(optimizer)  # 反缩放梯度
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 梯度裁剪
    scaler.step(optimizer)  # 更新 FP32 副本，转换为 FP16 更新模型
    scaler.update()  # 调整缩放因子
    
    # 5. 清零梯度
    optimizer.zero_grad()
```

### 3.3 梯度缩放（Gradient Scaling）

**问题**：FP16 的最小正数约为 $6 \times 10^{-8}$，很多梯度比这还小，会下溢为 0。

**解决方案**：先放大梯度，计算完再缩放回来。

```
原始梯度: [0.00001, 0.00002, 0.00003, ...]
                     ↓
         乘以缩放因子（如 1024）
                     ↓
缩放后梯度: [0.01024, 0.02048, 0.03072, ...]  ← 不会下溢了
                     ↓
           用缩放后梯度更新参数
                     ↓
         除以缩放因子恢复原始量级
```

**动态缩放**：

```python
class GradScaler:
    def __init__(self):
        self.scale_factor = 2**16  # 初始缩放因子
        self.growth_interval = 2000  # 每 2000 步尝试增大
        self.backoff_factor = 0.5  # 减小时的倍数
    
    def scale(self, loss):
        return loss * self.scale_factor
    
    def update(self):
        # 如果最近没有 inf/nan，尝试增大缩放因子
        if no_overflow_recently:
            self.scale_factor *= 2
        else:
            # 有 inf/nan，减小缩放因子
            self.scale_factor *= self.backoff_factor
```

### 3.4 BF16 不需要梯度缩放

```
BF16 的范围和 FP32 相同（±3.4 × 10³⁸），不会下溢
→ 不需要梯度缩放
→ 训练更简单、更稳定
→ 这是 BF16 的一大优势
```

## 四、混合精度的显存分析

### 4.1 各组件显存占用

| 组件 | FP32 训练 | 混合精度训练 | 节省 |
|------|----------|-------------|------|
| 模型参数 | 4N | 2N (FP16) + 4N (FP32 副本) | - |
| 梯度 | 4N | 2N (FP16) | 2x |
| 优化器状态 | 8N (Adam) | 8N (Adam) | 不变 |
| **总计** | **16N** | **16N** | **约 2x（梯度部分）** |

### 4.2 激活值显存

混合精度的激活值存储为 FP16，比 FP32 节省一半：

```
FP32 激活值: 4N bytes
FP16 激活值: 2N bytes → 节省 50%

对于 7B 模型，序列长度 2048：
FP32 激活: ~20 GB
FP16 激活: ~10 GB
```

### 4.3 显存优化技巧

| 技巧 | 效果 | 说明 |
|------|------|------|
| 激活检查点 | 节省显存 60-80% | 只保存部分激活，重计算其余 |
| 梯度累积 | 等效增大 batch size | 多步累积梯度再更新 |
| CPU Offload | 显存外的计算 | 把优化器状态放内存 |

## 五、混合精度的计算加速

### 5.1 Tensor Core 加速

NVIDIA GPU 的 Tensor Core 对低精度计算有专门优化：

| GPU | FP32 TFLOPS | FP16/BF16 TFLOPS | 加速比 |
|-----|-------------|------------------|--------|
| V100 | 15.7 | 125 (FP16) | 8x |
| A100 | 19.5 | 312 (BF16) | 16x |
| H100 | 67 | 990 (BF16) | 15x |

**实际加速**：混合精度训练通常比纯 FP32 快 **1.5-3x**（因为不是所有计算都能用 Tensor Core）。

### 5.2 通信加速

在分布式训练中，梯度同步的通信量也减半：

```
FP32 AllReduce: 通信量 = 4N × 2 × (P-1)/P bytes
FP16 AllReduce: 通信量 = 2N × 2 × (P-1)/P bytes → 节省 50%

对于 7B 模型，8 卡训练：
FP32 通信: ~28 GB/step
FP16 通信: ~14 GB/step
```

### 6.2 张量并行 + 混合精度

```
张量并行中的混合精度：

输入 X (FP16)
  ↓
GPU 0: Y₀ = X · W₀ (FP16 × FP16 → FP16)
GPU 1: Y₁ = X · W₁ (FP16 × FP16 → FP16)
  ↓
AllReduce (FP16 通信)
  ↓
输出 Y (FP16)

参数更新时：
FP32 副本 → 更新 → 转换为 FP16 → 存入模型
```

### 6.3 流水线并行 + 混合精度

```
流水线并行中的混合精度：

Stage 0 (GPU 0): FP16 前向 + FP16 反向
  ↓ 传递 FP16 激活
Stage 1 (GPU 1): FP16 前向 + FP16 反向
  ↓ 传递 FP16 激活
...

每个 stage 内部使用混合精度，stage 之间传递 FP16 数据
```

## 七、训练稳定性问题

### 7.1 Loss Spike

**现象**：训练过程中 Loss 突然飙升（spike），然后可能恢复或崩溃。

**原因**：

| 原因 | 说明 |
|------|------|
| 数值溢出 | FP16 范围有限，某些值超出范围 |
| 梯度爆炸 | 学习率太大或数据异常 |
| 数据质量问题 | 异常数据导致梯度异常 |

**解决方案**：

```python
# 1. 梯度裁剪
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

# 2. 学习率 warmup
scheduler = get_cosine_schedule_with_warmup(optimizer, 
    num_warmup_steps=2000, 
    num_training_steps=total_steps)

# 3. 检查点恢复
if loss > threshold:
    load_checkpoint(previous_checkpoint)
    reduce_learning_rate()
```

### 7.2 Loss Divergence

**现象**：Loss 持续上升，训练完全失败。

**常见原因**：

| 原因 | 排查方法 |
|------|---------|
| 学习率太大 | 降低学习率 |
| 梯度爆炸 | 检查梯度范数 |
| 数值不稳定 | 检查是否有 inf/nan |
| 数据问题 | 检查异常数据 |

### 7.3 BF16 vs FP16 的稳定性

| 指标 | FP16 | BF16 |
|------|------|------|
| Loss Spike 频率 | 较高 | 较低 |
| 需要梯度缩放 | 是 | 否 |
| 训练稳定性 | 一般 | 更好 |
| 推荐场景 | 旧 GPU（V100） | 新 GPU（A100/H100） |

## 八、面试高频问题

### Q1：什么是混合精度训练？为什么需要它？

> 混合精度训练同时使用 FP16/BF16（低精度）和 FP32（高精度）：低精度用于前向和反向计算（加速 + 省显存），高精度用于参数更新（稳定 + 精度高）。需要它的原因：(1) GPU 的 Tensor Core 对低精度有专门加速（8-16x）；(2) 低精度占用显存减半，能训练更大模型；(3) 通信量减半，分布式训练更快。

### Q2：FP16 和 BF16 有什么区别？为什么大模型更常用 BF16？

> FP16 指数 5 位、尾数 10 位，范围 ±6.55×10⁴，精度 3.3 位有效数字。BF16 指数 8 位（同 FP32）、尾数 7 位，范围 ±3.4×10³⁸，精度 2.4 位有效数字。BF16 范围大，几乎不会溢出/下溢，训练更稳定；FP16 需要动态损失缩放来避免下溢。大模型训练更常用 BF16，因为稳定性比精度更重要。

### Q3：什么是梯度缩放？为什么 FP16 需要它？

> 梯度缩放是解决 FP16 下溢问题的技术。FP16 的最小正数约 6×10⁻⁸，很多梯度比这还小会变成 0。做法是：前向传播后把 Loss 乘以一个大的缩放因子（如 1024），反向传播得到放大后的梯度，这样小梯度不会下溢；更新参数前再除以缩放因子恢复原始量级。动态缩放会根据是否有 inf/nan 自动调整缩放因子。BF16 不需要梯度缩放。

### Q4：混合精度训练的显存占用是多少？和纯 FP32 对比呢？

> 混合精度训练的显存占用：模型参数 2N（FP16）+ 4N（FP32 副本）+ 梯度 2N（FP16）+ 优化器状态 8N（Adam）= 16N。纯 FP32：参数 4N + 梯度 4N + 优化器 8N = 16N。看起来一样，但激活值存储为 FP16（2x 节省），所以实际显存节省约 30-50%。

### Q5：混合精度训练能加速多少？为什么？

> 实际加速约 1.5-3x，原因：(1) GPU 的 Tensor Core 对 FP16/BF16 有专门优化，理论算力是 FP32 的 8-16 倍；(2) 显存占用减小，可以用更大的 batch size；(3) 分布式训练中通信量减半。但不是所有计算都能用 Tensor Core（如 LayerNorm、Softmax 等），所以实际加速达不到理论值。

### Q6：训练时出现 Loss Spike 怎么办？

> Loss Spike 的原因可能是数值溢出、梯度爆炸或数据异常。解决方案：(1) 梯度裁剪（`clip_grad_norm_`）；(2) 学习率 warmup 和 decay；(3) 检查数据质量；(4) 如果 spike 严重，从最近的 checkpoint 恢复并降低学习率；(5) 考虑用 BF16 替代 FP16 以获得更好的稳定性。

## 九、总结

| 概念 | 核心要点 |
|------|---------|
| 混合精度 | FP16/BF16 计算 + FP32 更新 |
| BF16 vs FP16 | BF16 范围大、更稳定，是大模型首选 |
| 梯度缩放 | FP16 需要，防止梯度下溢 |
| Tensor Core | 低精度计算的硬件加速，8-16x 理论加速 |
| 实际加速 | 1.5-3x（受非 Tensor Core 计算限制） |

**一句话记忆**：

> 混合精度就是"用低精度做苦力（计算），用高精度管钱（更新）"——既快又稳。BF16 是"大号的低精度"（范围大），FP16 是"小号的低精度"（需要梯度缩放保护）。
