# 量化技术

> KV Cache 解决了推理时的重复计算问题，但还有一个问题：**模型太大，显卡放不下**。LLaMA 70B 的 FP16 模型需要 140 GB 显存，而消费级显卡只有 24 GB（如 4090）甚至 12 GB（如 4070 Ti）。量化技术就是把模型从高精度（FP32/FP16）压缩到低精度（INT8/INT4），用精度换显存和速度。

---

## 一、什么是量化

### 1.1 核心思想

**量化**：把模型权重和/或激活值从高精度数值（如 FP32、FP16）映射到低精度整数（如 INT8、INT4）。

```
原始权重（FP16）: [0.125, -0.875, 0.5625, -0.3125, ...]
                      ↓ 量化
量化后权重（INT4）: [1, -7, 4, -3, ...]（映射到 -7 ~ 7 的整数）
                      ↓ 反量化（推理时）
近似权重（FP16）: [0.125, -0.875, 0.5625, -0.3125, ...]（有损，但近似）
```

### 1.2 量化的好处

| 好处 | 说明 |
|------|------|
| **显存节省** | INT4 是 FP16 的 1/4，LLaMA 70B 从 140 GB 降到 35 GB |
| **推理加速** | 低精度计算更快（整数乘法比浮点快） |
| **带宽节省** | 从显存读取的数据量减少，缓解内存瓶颈 |
| **部署门槛降低** | 大模型可以在消费级显卡上运行 |

### 1.3 量化的代价

| 代价 | 说明 |
|------|------|
| **精度损失** | 低精度表示能力有限，模型性能会下降 |
| **量化误差** | 舍入误差累积，可能影响生成质量 |

## 二、量化基础概念

### 2.1 对称量化 vs 非对称量化

**对称量化（Symmetric Quantization）**：

```
将值映射到 [-127, 127]（INT8），以 0 为中心

公式: q = round(x / scale)
      scale = max(|x|) / 127

示例:
  原始值: [-0.8, -0.4, 0.0, 0.4, 0.8]
  scale = 0.8 / 127 ≈ 0.0063
  量化值: [-127, -63, 0, 63, 127]
```

**非对称量化（Asymmetric Quantization）**：

```
将值映射到 [0, 255]（UINT8），允许零点偏移

公式: q = round((x - zero_point) / scale)
      scale = (max(x) - min(x)) / 255
      zero_point = round(-min(x) / scale)

示例:
  原始值: [0.1, 0.3, 0.5, 0.7, 0.9]
  scale = (0.9 - 0.1) / 255 ≈ 0.00314
  zero_point = round(-0.1 / 0.00314) ≈ -32
  量化值: [0, 64, 128, 192, 255]
```

**对比**：

| 特性 | 对称量化 | 非对称量化 |
|------|---------|-----------|
| 量化范围 | [-127, 127] | [0, 255] |
| 零点 | 必须为 0 | 可以偏移 |
| 适合场景 | 权重（通常围绕 0 对称） | 激活值（可能非对称） |
| 计算复杂度 | 简单 | 稍复杂 |

### 2.2 Per-Tensor vs Per-Channel vs Per-Group

**量化粒度**：决定用一个 scale 还是多个 scale。

```
Per-Tensor（整个张量一个 scale）:
  整个权重矩阵 → 1 个 scale
  简单，但精度低

Per-Channel（每个通道一个 scale）:
  每个输出通道 → 1 个 scale
  精度高，但开销大

Per-Group（每 g 个元素一个 scale）:
  每 128 个权重 → 1 个 scale
  折中方案，最常用
```

**Per-Group 量化示例**：

```python
def per_group_quantize(weight, group_size=128, bits=4):
    """Per-Group INT4 量化"""
    # weight shape: (out_features, in_features)
    n_groups = weight.numel() // group_size
    
    # 重塑为 (n_groups, group_size)
    weight_grouped = weight.reshape(n_groups, group_size)
    
    # 每组计算 scale
    scale = weight_grouped.abs().max(dim=1).values / (2**(bits-1) - 1)
    
    # 量化
    weight_quant = (weight_grouped / scale.unsqueeze(1)).round()
    weight_quant = weight_quant.clamp(-8, 7)  # INT4 范围
    
    return weight_quant, scale
```

### 2.3 W4A16 vs W8A8 vs W4A8

| 量化方式 | 权重 | 激活值 | 特点 |
|---------|------|--------|------|
| **W4A16** | INT4 | FP16 | 权重压缩，激活不变，最常用 |
| **W8A8** | INT8 | INT8 | 权重和激活都量化，需要校准数据 |
| **W4A8** | INT4 | INT8 | 激进压缩，需要特殊技术 |

**命名规则**：W = Weight（权重），A = Activation（激活），数字 = 位数

## 三、量化方法分类

### 3.1 训练后量化（PTQ, Post-Training Quantization）

**特点**：在模型训练完成后进行量化，不需要重新训练。

```
训练好的模型（FP16）
      ↓ 量化
量化后的模型（INT4/INT8）
      ↓ 微调（可选）
量化后微调的模型
```

**代表方法**：

#### GPTQ（GPT Quantization）

```
核心思想：逐层量化，用 Hessian 信息最小化量化误差

步骤：
1. 准备校准数据（128 条样本）
2. 逐层量化权重
3. 用 Hessian 矩阵的逆来指导量化顺序
4. 量化后可以微调恢复精度

优点：精度高，支持 INT4/INT3
缺点：需要校准数据，量化过程较慢
```

```python
# 使用 GPTQ 量化的伪代码
from transformers import AutoModelForCausalLM, GPTQConfig

# 加载预训练模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-70b")

# 配置 GPTQ 量化
quantization_config = GPTQConfig(
    bits=4,                    # 量化位数
    dataset="c4",              # 校准数据集
    group_size=128,            # Per-Group 大小
    desc_act=True,             # 按激活值降序量化
)

# 量化
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-70b",
    quantization_config=quantization_config
)

# 保存量化后的模型
model.save_pretrained("llama-2-70b-gptq-4bit")
```

#### AWQ（Activation-aware Weight Quantization）

```
核心思想：不是所有权重都同等重要，重要权重（对激活值影响大的）要保护

步骤：
1. 分析激活值分布，找出"重要通道"
2. 对重要通道使用更高精度或缩放
3. 对不重要通道更激进量化

优点：精度比 GPTQ 更好（保护重要权重）
缺点：需要分析激活值
```

```python
# 使用 AWQ 量化的伪代码
from awq import AutoAWQForCausalLM

model = AutoAWQForCausalLM.from_pretrained("meta-llama/Llama-2-70b")

# 配置 AWQ
quant_config = {
    "zero_point": True,        # 非对称量化
    "q_group_size": 128,       # Per-Group 大小
    "w_bit": 4,                # 量化位数
    "version": "GEMM"          # 使用 GEMM 内核
}

# 量化
model.quantize(
    tokenizer,
    quant_config=quant_config,
    calib_data="pileval"       # 校准数据
)

# 保存
model.save_quantized("./llama-2-70b-awq-4bit")
```

#### GGUF/GGML（llama.cpp）

```
核心思想：为 CPU/边缘设备优化的量化格式

特点：
- 支持多种量化方案（Q4_0, Q4_K_M, Q5_K_M, Q8_0 等）
- 专门为 CPU 推理优化
- 可以在笔记本、手机上运行大模型
- llama.cpp 支持

量化类型：
  Q4_0: 4-bit，Per-Tensor，最简单
  Q4_K_M: 4-bit，Per-Group + K-Quant，中等质量
  Q5_K_M: 5-bit，精度更好
  Q8_0: 8-bit，精度最高
```

### 3.2 量化感知训练（QAT, Quantization-Aware Training）

**特点**：在训练过程中模拟量化，让模型适应低精度。

```
训练过程：
  前向传播: 权重 → 量化 → 反量化 → 计算
  反向传播: 用 STE（Straight-Through Estimator）近似梯度

优点：精度损失最小
缺点：需要重新训练，计算成本高
```

**STE（Straight-Through Estimator）**：

```python
# 量化是不可导的（round 操作），如何反向传播？
# STE: 在前向传播时量化，反向传播时假装没有量化

class QuantizeSTE(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale):
        # 前向: 真正量化
        return (x / scale).round() * scale
    
    @staticmethod
    def backward(ctx, grad_output):
        # 反向: 直接传递梯度（假装没量化）
        return grad_output, None
```

### 3.3 混合精度量化（Mixed-Precision Quantization）

```
核心思想：不同层用不同的量化精度

敏感层（Attention）: 用 INT8 或 FP16
不敏感层（FFN）: 用 INT4

如何判断敏感度：
1. 逐层量化，观察精度下降
2. 用 Hessian 矩阵分析
3. 用重要性指标（如激活值幅度）
```

## 四、量化精度对比

### 4.1 不同位数的性能

| 位数 | 模型大小（70B） | 显存需求 | 精度损失 |
|------|---------------|---------|---------|
| FP16 | 140 GB | 140 GB | 基准 |
| INT8 | 70 GB | 70 GB | < 0.5% |
| INT4（GPTQ） | 35 GB | 35 GB | 1-3% |
| INT4（AWQ） | 35 GB | 35 GB | 0.5-2% |
| INT3 | 26 GB | 26 GB | 3-8% |

### 4.2 不同方法的对比

| 方法 | 量化方式 | 校准数据 | 速度 | 精度 |
|------|---------|---------|------|------|
| GPTQ | PTQ | 需要（128 条） | 快 | 高 |
| AWQ | PTQ | 需要（少量） | 快 | 最高 |
| GGUF | PTQ | 不需要 | 中 | 中 |
| QAT | QAT | 需要训练数据 | 慢 | 最高 |

`★ Insight ─────────────────────────────────────`
**AWQ 为什么比 GPTQ 精度更好？** GPTQ 对所有权重一视同仁地量化，但 AWQ 发现：激活值大的通道对应的权重更重要（因为小的量化误差会被激活值放大）。AWQ 对这些重要通道保护（用更高精度或缩放），所以整体精度更好。
`─────────────────────────────────────────────────`

## 五、量化的实际应用

### 5.1 使用 llama.cpp 运行量化模型

```bash
# 下载 GGUF 格式的量化模型
# 例如：TheBloke/Llama-2-70B-Chat-GGUF

# 运行 Q4_K_M 量化模型
./main -m llama-2-70b-chat.Q4_K_M.gguf \
       -n 512 \
       --temp 0.7 \
       -p "你好，请介绍一下自己"
```

### 5.2 使用 vLLM 运行 GPTQ/AWQ 模型

```python
from vllm import LLM, SamplingParams

# 加载 GPTQ 量化模型
llm = LLM(
    model="TheBloke/Llama-2-70B-Chat-GPTQ",
    quantization="gptq",
    dtype="float16"
)

# 生成
outputs = llm.generate(
    ["你好，请介绍一下自己"],
    SamplingParams(temperature=0.7, max_tokens=512)
)
```

### 5.3 使用 transformers 加载量化模型

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载 GPTQ 量化模型
model = AutoModelForCausalLM.from_pretrained(
    "TheBloke/Llama-2-70B-Chat-GPTQ",
    device_map="auto",
    trust_remote_code=True
)

# 加载 AWQ 量化模型
model = AutoModelForCausalLM.from_pretrained(
    "TheBloke/Llama-2-70B-Chat-AWQ",
    device_map="auto"
)
```

## 六、量化与其他优化的结合

### 6.1 量化 + KV Cache 优化

```
模型权重: INT4 量化（35 GB）
KV Cache: INT8 量化（节省 50%）
注意力: GQA（KV Cache 再减 75%）

总显存: 35 GB + 很小的 KV Cache → 单卡可跑 70B
```

### 6.2 量化 + 推测解码

```
大模型: INT4 量化（慢但准）
小模型: INT8 量化（快但不太准）

推测解码: 小模型快速生成草稿 → 大模型一次性验证
```

### 6.3 量化 + 张量并行

```python
# 多卡推理时，每张卡加载量化后的模型
# 例如 70B INT4，4 张 24GB 显卡

from vllm import LLM

llm = LLM(
    model="TheBloke/Llama-2-70B-Chat-GPTQ",
    quantization="gptq",
    tensor_parallel_size=4  # 4 张卡
)
```

## 七、面试高频问题

### Q1：什么是量化？为什么需要量化？

> 量化是把模型权重和/或激活值从高精度（FP16/FP32）映射到低精度（INT8/INT4）的技术。需要量化的原因：(1) 大模型显存占用太大，70B 模型 FP16 需要 140 GB，消费级显卡放不下；(2) 推理速度受限于显存带宽，量化后数据量减小，读取更快；(3) 量化可以降低部署成本，让大模型在更便宜的硬件上运行。

### Q2：GPTQ 和 AWQ 有什么区别？

> 两者都是训练后量化（PTQ）方法，区别在于：**GPTQ** 逐层量化，用 Hessian 信息最小化量化误差，对所有权重一视同仁。**AWQ** 是激活感知量化，分析激活值分布，保护对激活值影响大的重要通道（因为小的量化误差会被激活值放大）。AWQ 精度通常更好（0.5-2% 损失 vs GPTQ 的 1-3%），但需要分析激活值。

### Q3：Per-Group 量化是什么？为什么常用？

> Per-Group 量化把权重分成固定大小的组（如 128 个元素），每组独立计算 scale 和 zero_point 进行量化。相比 Per-Tensor（整个矩阵一个 scale），Per-Group 精度更高，因为不同组的值分布可能差异很大。相比 Per-Channel，Per-Group 计算更简单。group_size=128 是常用折中，在精度和开销之间平衡良好。

### Q4：INT4 量化的精度损失有多大？

> 取决于量化方法和模型。AWQ INT4 通常只有 0.5-2% 的精度损失（在大多数基准测试上），GPTQ INT4 约 1-3%。对于 70B 模型，量化后的性能通常仍然优于更小的未量化模型（如量化后的 70B 仍然比未量化的 13B 强）。实际使用中，INT4 量化几乎不影响日常对话、摘要、翻译等任务。

### Q5：W4A16 和 W8A8 有什么区别？

> **W4A16**：权重 INT4，激活 FP16。只量化权重，激活保持高精度。优点是实现简单，不需要校准数据；缺点是激活的 INT4 量化很难（激活值分布不稳定）。**W8A8**：权重和激活都 INT8。优点是计算更快（整数矩阵乘法）；缺点是需要校准数据确定激活的 scale，且对异常值敏感。W4A16 是目前最常用的方案。

### Q6：GGUF 是什么？它和其他量化格式有什么区别？

> GGUF（GPT-Generated Unified Format）是 llama.cpp 使用的量化格式，专门为 CPU/边缘设备推理优化。特点：(1) 支持多种量化方案（Q4_0, Q4_K_M, Q5_K_M 等），Q4_K_M 用 Per-Group + K-Quant 精度较好；(2) 专门为 CPU SIMD 指令优化；(3) 可以在笔记本、手机上运行大模型。相比之下，GPTQ/AWQ 主要针对 GPU 推理。

## 八、总结

| 方法 | 类型 | 位数 | 精度 | 适用场景 |
|------|------|------|------|---------|
| GPTQ | PTQ | 4/3 bit | 高 | GPU 推理 |
| AWQ | PTQ | 4 bit | 最高 | GPU 推理（推荐） |
| GGUF | PTQ | 4-8 bit | 中 | CPU/边缘推理 |
| QAT | QAT | 4 bit | 最高 | 追求极致精度 |

**一句话记忆**：

> 量化就是"压缩照片"——把高清图（FP16）压缩成低分辨率（INT4），文件变小了（省显存），加载变快了（推理加速），看起来还是那张图（精度损失小）。AWQ 是"聪明压缩"（保护重要部分），GPTQ 是"均匀压缩"，GGUF 是"手机适配压缩"。
