# 注意力机制（Attention）详解

> [[Transformer.md]] 讲了 Self-Attention 的基础原理（Q、K、V、多头注意力），本文从**核心公式和物理含义**讲起，深入讲解注意力机制的各种高效变体（Flash Attention、稀疏注意力、线性注意力等），帮你完整理解现代大模型如何高效处理长序列。

---

## 一、Attention 基础回顾

### 1.1 核心公式与物理含义

Attention 的本质：**模型应该关注输入中的重要部分，而忽略不重要的部分。** 根据当前需求，从上下文中按比例提取信息，生成一个新的特征表示。

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$

### 1.2 具象理解：语义对齐（以"苹果"为例）

假设输入序列为：`["我", "吃", "苹果"]`。我们重点观察 Token "苹果"是如何通过 Attention 确定自己是"水果"而不是"手机"的。

| 组件 | 符号 | 物理含义 | 形象化描述 |
|------|------|----------|-----------|
| 查询（Query） | $Q$ | "我需要什么？" | "苹果"发出询问："我周围有没有关于'动作'或'食物'属性的词，能帮我确定身份？" |
| 键（Key） | $K$ | "我有什么标签？" | "吃"的标签是"动作、进食"；"我"的标签是"动作主体、水果、水滴电子产品" |
| 值（Value） | $V$ | "我包含什么信息？" | "吃"提供的具体信息是"含有'动作'特征"；"苹果"自己提供的信息是"多汁、甜" |

**计算逻辑**：

1. **匹配**（$Q \cdot K^T$）："苹果"的 $Q$ 与"吃"的 $K$ 匹配度较高（动作关系），同时"苹果"的 $Q$ 与自身的 $K$ 匹配度也非常高。
2. **分配权重**：经过 Softmax，模型给"自身"分配 60% 权重，给"吃"分配 30% 权重，剩下 10% 分配给其他词。
3. **融合**（$Weight \cdot V$）：输出向量 $= 0.6 \times V_{苹果} + 0.3 \times V_{吃} + \dots$
4. **结果**：更新后的"苹果"向量带有了"动作"的特征，从而让后续层明确这指的是"食物"。

### 1.3 数值推演：掩码与权重的变化

假设序列长度 $S=3$，特征维度 $d_k=2$。

#### Step 1：计算原始分数（Scores）

计算 $Q \cdot K^T$ 得到 $3 \times 3$ 矩阵，注意：对角线（自己看自己）通常分值最高。

$$\text{Scores} = \begin{bmatrix} 10 & 2 & 1 \\ 5 & 10 & 3 \\ 2 & 8 & 10 \end{bmatrix}$$

#### Step 2：因果掩码（Causal Masking）

在 GPT 等 Decoder 架构中，为了防止模型在训练时"偷看"后文，我们将上三角（未来信息）设为 $-\infty$。

$$\text{Masked Scores} = \begin{bmatrix} 10 & -\infty & -\infty \\ 5 & 10 & -\infty \\ 2 & 8 & 10 \end{bmatrix}$$

**物理意义**：单词"吃"只能看到"我"和"吃"，看不到后面的"苹果"。

#### Step 3：归一化（Softmax）

对每一行进行 Softmax，使每一行的总和等于 1。

$$\text{Weights} = \begin{bmatrix} 1.0 & 0.0 & 0.0 \\ 0.01 & 0.99 & 0.0 \\ 0.00 & 0.12 & 0.88 \end{bmatrix}$$

**观察**：最后一行"苹果"对自身的关注度最高（0.88），同时从"吃"那里吸收了 0.12 的能量。

### 1.4 缩放因子 $\sqrt{d_k}$ 的意义

公式中除以 $\sqrt{d_k}$ 是为了解决**梯度消失**问题。

- **现象**：随着维度 $d_k$ 增大，点积的方差会变得很大，导致 Scores 中出现极大的数值（如 100）。
- **后果**：Softmax 函数在输入值很大时，其导数（梯度）趋近于 0（饱和区）。
- **解决方案**：通过除以 $\sqrt{d_k}$，将分数的分布拉回到 0 附近，确保信号在传输过程中既不过载也不消失，让模型能够通过梯度下降进行学习。

`★ Insight ─────────────────────────────────────`
**缩放因子的本质**：假设 $Q$ 和 $K$ 的每个元素独立同分布，均值为 0，方差为 1。那么 $d_k$ 个元素的点积均值为 0，**方差为 $d_k$**。除以 $\sqrt{d_k}$ 把方差拉回 1，保证 softmax 处于梯度良好的区域。
`─────────────────────────────────────────────────`

### 1.5 代码实现

```python
import torch
import math
from torch.nn import softmax  # 使用 PyTorch 实现的数值稳定版 Softmax

def scaled_dot_product_attention(
    Q: torch.Tensor,
    K: torch.Tensor,
    V: torch.Tensor,
    mask: torch.Tensor = None
) -> torch.Tensor:
    """
    参数:
    Q: [..., n, d_k] (n 为查询序列长度)
    K: [..., m, d_k] (m 为键值序列长度)
    V: [..., m, d_v]
    mask: [n, m] 布尔张量，True 为保留，False 为屏蔽
    """
    d_k = Q.size(-1)
    
    # 1. 计算原始分数 (scores)
    # einsum 语义：沿着 d_k 维度进行点积，保留 batch(...)、query(n) 和 key(m) 维度
    # 结果形状：[..., n, m]
    scores = torch.einsum('...nk,...mk->...nm', Q, K) / math.sqrt(d_k)
    
    # 2. 应用掩码 (Masking)
    if mask is not None:
        # 将 mask 中为 False（需屏蔽）位置的分数设为负无穷，使其在 Softmax 后概率为 0
        scores = scores.masked_fill(mask == False, float('-inf'))
    
    # 3. 计算注意力权重（归一化）
    # dim=-1: 对应的 Query 对所有 Key 的分布
    probs = softmax(scores, dim=-1)
    
    # 4. 加权求和得到输出 (Output)
    # einsum 语义：利用 probs(n, m) 对 V(m, k) 进行加权求和
    # 结果形状：[..., n, d_v]
    output = torch.einsum('...nm,...mk->...nk', probs, V)
    
    return output
```

## 二、标准 Attention 的瓶颈

### 2.1 计算复杂度回顾

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| $QK^T$ | $O(n^2 d)$ | $O(n^2)$（存储注意力矩阵） |
| softmax | $O(n^2)$ | $O(n^2)$ |
| $\times V$ | $O(n^2 d)$ | $O(nd)$ |

**核心瓶颈**：$O(n^2)$ 的注意力矩阵——当序列长度 $n$ 从 2K 增加到 128K，显存占用增加 **4096 倍**。

### 2.2 内存访问瓶颈（Memory Wall）

GPU 计算速度快，但显存访问慢（HBM 带宽有限）：

```
计算 vs 访存的差距：
- 算力（FLOPS）：312 TFLOPS（A100）
- 带宽（Bandwidth）：2 TB/s（A100 HBM）
- 比值：~150 FLOPS/Byte

标准 Attention：
- 读写 n×n 的注意力矩阵 → 大量 HBM 访问
- 算术强度低 → GPU 算力浪费
```

## 三、Cross-Attention（交叉注意力）

### 3.1 与 Self-Attention 的区别

| 类型 | Q、K、V 来源 | 用途 |
|------|-------------|------|
| Self-Attention | Q、K、V 都来自**同一个**序列 | 序列内部建模 |
| Cross-Attention | Q 来自一个序列，K、V 来自**另一个**序列 | 跨模态/跨序列融合 |

```
Self-Attention：
Encoder 输出: [a₁ a₂ a₃] → Q, K, V → 注意力矩阵

Cross-Attention：
Decoder 当前层: [b₁] → Q
Encoder 输出:  [a₁ a₂ a₃] → K, V
→ b₁ 关注 a₁, a₂, a₃ 的权重
```

### 3.2 Cross-Attention 的应用

| 应用场景 | 说明 |
|---------|------|
| 机器翻译 | Decoder 的 Q 关注 Encoder 的 K、V |
| 多模态模型 | 文本 Q 关注图像 K、V（如 LLaVA） |
| RAG | 问题 Q 关注检索文档的 K、V |
| ControlNet | 条件特征 K、V 注入到生成模型 |

### 3.3 Cross-Attention 的 KV Cache

Cross-Attention 的 K、V 在推理时**不随新 token 变化**（输入序列固定），所以可以：
1. 预计算并缓存
2. 在整个生成过程中复用
3. 不需要像 Self-Attention 那样每步更新

## 四、常见面试问题

**Q1：请写出 Attention 的计算公式**

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$

其中：
- $Q = XW_Q$，$K = XW_K$，$V = XW_V$（$W_Q$、$W_K$、$W_V$ 是可学习矩阵）
- 除以 $\sqrt{d_k}$ 是为了防止点积值过大导致 softmax 梯度消失

---

**Q2：GQA 的广播操作（第5步）为什么需要把 KV 头广播到和 Q 头数一样？具体是怎么实现的？**

GQA（Grouped Query Attention）中，Q 的头数（如 32）多于 KV 的头数（如 8），每个 KV 头要**服务多个 Q 头**。

广播的必要性：
- Q: `[batch, n_heads=32, seq_len, head_dim]`
- KV: `[batch, n_kv_heads=8, seq_len, head_dim]`
- 直接做点积形状不匹配，需要将 KV 扩展到 32 头

实现方式：
```python
# 方法1：repeat_interleave
k_expanded = k.repeat_interleave(n_heads // n_kv_heads, dim=1)

# 方法2：expand（零开销，PyTorch 自动广播）
k_expanded = k.unsqueeze(1).expand(-1, n_heads // n_kv_heads, -1, -1, -1)
k_expanded = k_expanded.reshape(batch, n_heads, seq_len, head_dim)
```

本质：8 个 KV 头，每个重复 4 次 → 32 个，与 Q 一一对应。

---

**Q3：KV Cache 的工作原理 —— Prefill 阶段和 Decode 阶段的 KV Cache 有什么不同？为什么能加速推理？**

| 阶段 | 操作 | KV Cache 状态 |
|------|------|---------------|
| Prefill | 一次性处理整个输入序列 | 缓存所有输入 token 的 K、V |
| Decode | 逐个生成新 token | 每步只计算新 token 的 q/k/v，将 k/v 追加到 cache |

加速原理：
1. **避免重复计算**：已生成 token 的 K、V 不需要重新计算
2. **减少计算量**：每步只需 1 个 token 的 Q 与所有 K 做点积，而不是重新计算整个序列
3. **显存换算力**：用 $O(n)$ 的缓存空间换取 $O(n^2)$ → $O(n)$ 的计算量

```
无 KV Cache：每步重新计算全部 K、V → O(n²) per step
有 KV Cache：只计算新 token 的 k、v → O(n) per step
```

---

**Q4：因果 mask 的作用 —— 为什么需要 `torch.triu(..., diagonal=1)`？去掉这个 mask 会发生什么？**

`torch.triu(..., diagonal=1)` 创建上三角矩阵，将未来位置设为 True（需屏蔽）。

作用：**防止信息泄露**——每个 token 只能关注自己和之前的 token，不能"偷看"未来。

去掉 mask 的后果：
- 训练时：模型可以直接看到答案，导致训练 loss 虚低，但实际生成时效果很差
- 推理时：自回归生成无法进行（因为推理时根本不知道未来的 token）

```python
# 因果 mask 创建
mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool()
# [[False,  True,  True],
#  [False, False,  True],
#  [False, False, False]]
```

---

**Q5：注意力分数为什么要除以 $\sqrt{d_k}$？不这么做会有什么后果？**

原因：**防止点积值过大导致 softmax 梯度消失**。

数学推导：
- 假设 Q、K 的每个元素独立同分布，均值 0，方差 1
- $d_k$ 维点积的均值为 0，**方差为 $d_k$**
- 当 $d_k=128$ 时，点积值可能达到 $\pm 20$ 以上

不除以 $\sqrt{d_k}$ 的后果：
| 问题 | 表现 |
|------|------|
| 点积值过大 | softmax 输入值极端（如 100 vs -100） |
| softmax 饱和 | 输出接近 one-hot，梯度趋近于 0 |
| 训练失败 | 模型无法通过梯度下降学习 |

除以 $\sqrt{d_k}$ 后：点积方差从 $d_k$ 变回 1，softmax 输入保持在合理范围。

## 五、总结

### 5.1 速查表

| 概念 | 核心要点 |
|------|---------|
| Attention 公式 | $\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$ |
| Q、K、V | Q="我需要什么"，K="我有什么标签"，V="我包含什么信息" |
| 缩放因子 $\sqrt{d_k}$ | 防止点积过大导致 softmax 梯度消失 |
| 计算复杂度 | $O(n^2 d)$ 时间，$O(n^2)$ 空间 |
| 核心瓶颈 | $n \times n$ 的注意力矩阵，显存随序列长度平方增长 |
| Self-Attention | Q、K、V 来自同一序列，用于序列内部建模 |
| Cross-Attention | Q 来自一个序列，K、V 来自另一个序列，用于跨模态融合 |
