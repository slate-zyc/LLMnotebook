# 自回归生成（Autoregressive Generation）

> 你前面学了 Transformer 架构（模型怎么处理 token）、Tokenizer（文本怎么切分为 token），但还有一个关键问题没回答：**模型给出下一个 token 的概率分布之后，具体怎么"选"出 token？** 这就是自回归生成要解决的问题。
>
> 自回归生成是所有 Decoder-Only 大模型（GPT、LLaMA、Qwen、DeepSeek）生成文本的核心机制。理解它，你才能真正明白为什么同一个模型在不同参数下输出风格迥异，以及推理优化（KV Cache、量化）到底在加速什么。

---

## 一、什么是自回归生成？

### 1.1 核心定义

> **自回归（Autoregressive）**：每一步的输出都依赖于之前所有步骤的输出，逐步"自产自销"地生成序列。

数学表达：生成序列 $y_1, y_2, ..., y_T$ 的概率分解为：

$$P(y_1, y_2, ..., y_T) = \prod_{t=1}^{T} P(y_t \mid y_1, y_2, ..., y_{t-1})$$

直觉理解：**每次只生成一个 token，生成的 token 会拼到输入后面，作为下一步的条件。**

### 1.2 生成过程详解

```
输入：你是谁

Step 1：模型看到 [你是谁]
        → 预测下一个 token 的概率分布
        → 选出 token："我"
        输出序列：[我]

Step 2：模型看到 [你是谁，我]
        → 预测下一个 token 的概率分布
        → 选出 token："是"
        输出序列：[我，是]

Step 3：模型看到 [你是谁，我，是]
        → 预测下一个 token 的概率分布
        → 选出 token："一"
        输出序列：[我，是，一]

Step 4：模型看到 [你是谁，我，是，一]
        → 预测下一个 token 的概率分布
        → 选出 token："个"
        输出序列：[我，是，一，个]

... 持续直到生成 <|eos|> 或达到最大长度
```

`★ Insight ─────────────────────────────────────`
注意每一步模型都重新处理**整个序列**（包括之前生成的所有 token），而不是只看最新生成的 token。这就是为什么推理速度随着上下文变长而变慢——每一步的计算量在增长。KV Cache 就是为了优化这一点（见第四节）。
`─────────────────────────────────────────────────`

### 1.3 训练 vs 推理的区别

| 阶段 | 输入 | 处理方式 | 速度 |
|------|------|---------|------|
| **训练** | 完整的输入 + 目标序列 | **一次前向传播**，所有位置并行计算损失（Teacher Forcing） | 快（GPU 并行） |
| **推理** | 只有输入（prompt） | **逐步生成**，每一步一次前向传播 | 慢（串行） |

训练时使用 **Teacher Forcing**：把完整的目标序列一次性喂给模型，用 Masked Attention 确保每个位置只能看到前面的 token，然后所有位置同时计算 loss。这是并行的。

推理时无法并行：因为下一步的输入依赖上一步的输出，必须等上一步完成才能开始。

## 二、解码策略（Decoding Strategies）

模型每一步输出的是一个**概率分布**（vocab_size 维的向量经过 softmax），但最终只能选一个 token。**怎么从概率分布中选出 token，就是解码策略要解决的问题。**

### 2.1 Greedy Search（贪心搜索）

最简单的策略：**每一步选概率最大的 token。**

```
Step 1: P("我")=0.4, P("你")=0.3, P("他")=0.1, ...  → 选 "我"
Step 2: P("是")=0.5, P("在")=0.2, ...               → 选 "是"
Step 3: P("一")=0.3, P("个")=0.25, ...              → 选 "一"
```

**代码实现**：

```python
# Greedy Search：每步选概率最高的 token
next_token = logits.argmax(dim=-1)
```

**优点**：速度最快，每步只需取 argmax。

**缺点**：容易陷入局部最优，生成的内容重复、无趣。

```
问题示例：
  Greedy 选的路径：我 → 是 → 一 → 个 → 好 → 人 → 好 → 人 → 好 → 人 ...（重复！）
  
  实际最优路径（整体概率更高）：
  我 → 是 → 一 → 个 → 学 → 生 → 喜 → 欢 → 编 → 程
```

### 2.2 Beam Search（束搜索）

每一步保留 **B 个** 最优候选序列（beam width），最终选总概率最高的。

```
假设 beam_width = 2：

Step 1:
  候选1: [我]    P=0.4
  候选2: [你]    P=0.3     ← 保留 top-2

Step 2: 对每个候选扩展所有可能的 token，计算累积概率
  [我, 是]  P = 0.4 × 0.5 = 0.20
  [我, 在]  P = 0.4 × 0.2 = 0.08
  [你, 好]  P = 0.3 × 0.6 = 0.18
  [你, 是]  P = 0.3 × 0.3 = 0.09
  
  保留 top-2：
  候选1: [我, 是]  P=0.20
  候选2: [你, 好]  P=0.18

Step 3: 继续扩展 ...
  直到所有候选生成 <|eos|>，选总概率最高的
```

**优点**：比贪心搜索能找到更好的全局最优解。

**缺点**：需要 B 倍的计算资源和显存，速度慢。

| 场景 | 推荐 beam width |
|------|----------------|
| 机器翻译 | 4~10（质量优先） |
| 文本摘要 | 3~5 |
| 开放式对话 | 通常不用 beam search |

### 2.3 Sampling（采样）

不选概率最大的，而是**按概率随机采样**——概率高的更容易被选中，但概率低的也有机会。

$$P(\text{选中 token}_i) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

其中 $T$ 是**温度参数（Temperature）**。

**代码实现**：

```python
# 随机采样：按概率分布采样下一个 token
probs = F.softmax(logits / temperature, dim=-1)
next_token = torch.multinomial(probs, num_samples=1)
```

#### 温度的作用

```
原始 logits: [2.0, 1.0, 0.5, 0.1]

T = 0.1（低温）: softmax → [0.99, 0.01, 0.00, 0.00]  ← 几乎总是选最大的（接近 Greedy）
T = 1.0（标准）: softmax → [0.52, 0.22, 0.15, 0.11]  ← 原始分布
T = 2.0（高温）: softmax → [0.35, 0.26, 0.21, 0.18]  ← 分布更平坦，更多样
```

| 温度 | 效果 | 适用场景 |
|------|------|---------|
| T → 0 | 接近 Greedy，确定性强 | 代码生成、事实问答 |
| T = 1.0 | 原始概率分布 | 通用对话 |
| T > 1.0 | 更随机、更多样 | 创意写作、头脑风暴 |
| T → ∞ | 均匀随机 | 不实用 |

### 2.4 Top-k Sampling

从概率最高的 **k 个** token 中采样，其余 token 直接丢弃（概率设为 0）。

**代码实现**：

```python
# Top-k 采样：只从概率最高的 k 个 token 中采样
topk_logits, topk_indices = logits.topk(k)
topk_probs = F.softmax(topk_logits / temperature, dim=-1)
next_token_idx = torch.multinomial(topk_probs, num_samples=1)
next_token = topk_indices.gather(-1, next_token_idx)
```

```
假设 k = 3：
  原始概率：[0.4, 0.3, 0.1, 0.05, 0.03, 0.02, ...]
  保留 top-3：[0.4, 0.3, 0.1]
  重新归一化：[0.5, 0.375, 0.125]
  从这 3 个中采样
```

**问题**：k 是固定值，但每一步的分布"形状"不同。有时 top-1 的概率是 0.9（此时 k=3 也基本等于 Greedy），有时 top-1 只有 0.1（此时 k=3 可能丢掉了有意义的候选）。

### 2.5 Top-p Sampling（Nucleus Sampling）⭐

> **这是目前最主流的采样策略，GPT、LLaMA、Qwen 默认都使用它。**

选择概率累积达到 **p** 的最小 token 集合，从中采样。集合大小是动态的。

**代码实现**：

```python
# Top-p 采样（Nucleus Sampling）：选择概率累积超过 p 的最小 token 集合
sorted_logits, sorted_indices = logits.sort(descending=True)
sorted_probs = F.softmax(sorted_logits / temperature, dim=-1)
cumulative_probs = sorted_probs.cumsum(dim=-1)

# 找到累积概率超过 p 的位置，将其 logits 设为 -inf
mask = cumulative_probs - sorted_probs > p
sorted_logits[mask] = -float('inf')

# 在剩余的 token 中采样
probs = F.softmax(sorted_logits / temperature, dim=-1)
next_token_idx = torch.multinomial(probs, num_samples=1)
next_token = sorted_indices.gather(-1, next_token_idx)
```

```
假设 p = 0.9：

情况 A（分布集中）：
  token 概率：[0.85, 0.10, 0.02, 0.01, ...]
  累积概率： [0.85, 0.95 ← 达到 0.9]
  只取前 2 个 token 采样

情况 B（分布平坦）：
  token 概率：[0.15, 0.12, 0.11, 0.10, 0.09, 0.08, ...]
  累积概率： [0.15, 0.27, 0.38, 0.48, 0.57, 0.65, 0.72, 0.78, 0.83, 0.87, 0.90 ← 达到 0.9]
  取前 10 个 token 采样
```

**优势**：候选集合大小随分布形状自适应调整，避免了 top-k 的固定阈值问题。

### 2.6 重复惩罚（Repetition Penalty）

Greedy 和采样策略都容易出现**重复生成**的问题（同一个词或短语反复出现）。Repetition Penalty 通过降低已出现 token 的概率来抑制重复：

```python
# 对已经出现过的 token 的 logits 施加惩罚
if repetition_penalty != 1.0:
    # logits > 0 的除以 penalty，logits < 0 的乘以 penalty
    score = logits.gather(-1, prev_tokens)
    score = torch.where(score > 0, score / repetition_penalty, score * repetition_penalty)
    logits.scatter_(-1, prev_tokens, score)
```

| `repetition_penalty` | 效果 |
|---------------------|------|
| = 1.0 | 无惩罚（默认） |
| > 1.0（如 1.1） | 已出现的 token 概率被压低，抑制重复 |
| < 1.0（如 0.9） | 鼓励重复（极少使用） |

`★ Insight ─────────────────────────────────────`
注意 `repetition_penalty` 和 `temperature`、`top_p` 的作用阶段不同：repetition_penalty 在 logits 层面操作（softmax 之前），直接修改已出现 token 的原始分数；而 temperature 和 top_p 在概率层面操作（softmax 之后）。所以 repetition_penalty 是最先执行的，它改变了 logits 分布，后续的采样策略在此基础上工作。
`─────────────────────────────────────────────────`

### 2.7 策略对比与组合

实际使用中，通常**组合多种策略**：

```python
# 典型配置
temperature = 0.7
top_k = 50
top_p = 0.9
repetition_penalty = 1.1
```

```
Temperature + Top-p + Top-k + Repetition Penalty 的典型组合：

创意写作：T=1.2, top_p=0.95, top_k=50,   rp=1.1  ← 高多样性 + 抑制重复
通用对话：T=0.7, top_p=0.9,  top_k=40,   rp=1.1  ← 平衡
代码生成：T=0.2, top_p=0.95, top_k=10,   rp=1.0  ← 低随机性，代码本身重复是正常的
事实问答：T=0.0, top_p=1.0,  top_k=1,    rp=1.0  ← Greedy，无需随机性
```

`★ Insight ─────────────────────────────────────`
调参的执行顺序很重要：先对 logits 施加 `repetition_penalty`（惩罚已出现 token），再用 `temperature` 缩放（控制分布形状），最后用 `top_p` / `top_k` 过滤候选（决定采样范围）。这个顺序决定了每个参数的生效逻辑——如果反过来先过滤候选再施加惩罚，惩罚就可能失效。
`─────────────────────────────────────────────────`

`★ Insight ─────────────────────────────────────`
Temperature 和 Top-p 作用在不同环节：Temperature 改变概率分布的"形状"（平滑/尖锐），Top-p 在确定形状后决定"保留多少候选"。一般不要同时设 T=0 和 top_p<1，因为 T=0 后分布是确定性的，Top-p 就没有意义了。
`─────────────────────────────────────────────────`

## 三、停止条件

自回归生成不会无限进行，需要停止条件：

| 停止条件 | 说明 | 优先级 |
|---------|------|--------|
| 生成 `<\|eos\|>` | 模型认为序列已完成 | 最高 |
| 达到 `max_tokens` | 强制限制最大长度 | 兜底 |
| 达到 `stop_sequences` | 用户指定的停止词 | 中 |
| 达到上下文窗口上限 | 模型能处理的最大长度 | 兜底 |

```python
# OpenAI API 的停止条件示例
response = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "你好"}],
    max_tokens=100,           # 最多生成 100 个 token
    stop=["\n\n", "END"],     # 遇到这些字符串停止
    temperature=0.7,
    top_p=0.9
)
```

## 四、KV Cache（键值缓存）

### 4.1 为什么需要 KV Cache？

回到自回归的核心问题：每一步都要对**整个序列**做 Self-Attention。

```
Step 1: 处理 [x₁, x₂, ..., x_n]           → n 个 token
Step 2: 处理 [x₁, x₂, ..., x_n, y₁]       → n+1 个 token
Step 3: 处理 [x₁, x₂, ..., x_n, y₁, y₂]   → n+2 个 token
...
Step t: 处理 [x₁, ..., x_n, y₁, ..., y_{t-1}] → n+t-1 个 token
```

每一步都在重复计算前面所有 token 的 K 和 V 向量——这非常浪费！

### 4.2 KV Cache 的原理

> **把之前算过的 K、V 缓存起来，每一步只计算新 token 的 K、V，然后拼接到缓存上。**

```
没有 KV Cache：
  Step t 需要计算：Q（n+t-1个）× K^T（n+t-1个）× V（n+t-1个）
  复杂度：O((n+t)² × d)

有 KV Cache：
  Step t 只需计算：Q（1个）× K^T（缓存的 n+t-1 个）× V（缓存的 n+t-1 个）
  复杂度：O((n+t) × d)
```

```
KV Cache 工作流程：

Step 1: 处理 prompt [x₁, x₂, ..., x_n]
        → K_cache = [k₁, k₂, ..., k_n]
        → V_cache = [v₁, v₂, ..., v_n]
        → Q_new = q_{n+1}
        → Attention(q_{n+1}, K_cache, V_cache) → 生成 y₁

Step 2: 只处理新 token [y₁]
        → K_cache = [k₁, ..., k_n, k_{n+1}]  （追加）
        → V_cache = [v₁, ..., v_n, v_{n+1}]  （追加）
        → Q_new = q_{n+2}
        → Attention(q_{n+2}, K_cache, V_cache) → 生成 y₂

... 每步只做 1 个 token 的前向传播 + 长度为 n+t 的 Attention
```

### 4.3 KV Cache 的显存占用

KV Cache 是推理时显存的主要消耗之一：

$$\text{KV Cache 大小} = 2 \times L \times n \times d_{kv} \times \text{dtype\_bytes}$$

其中 $L$ 是层数，$n$ 是当前序列长度，$d_{kv}$ 是 KV 头的总维度。

以 LLaMA 2 70B 为例：

| 参数 | 值 |
|------|-----|
| 层数 L | 80 |
| KV 头维度 $d_{kv}$ | 128 × 8（GQA 组数）= 1024 |
| 序列长度 4096 | 每层 4096 × 1024 × 2（FP16）= 8MB |
| **总 KV Cache** | **80 × 8MB = 640MB** |

`★ Insight ─────────────────────────────────────`
这就是 GQA（分组查询注意力）对推理的重大意义：MHA 的 KV 头维度是 d_k × h（如 128 × 64 = 8192），而 GQA 只需要 d_k × g（如 128 × 8 = 1024），**KV Cache 直接减少到 1/8**。所以 LLaMA 2 70B 和 Qwen 2.5 选择 GQA，不只是训练时更快，更重要的是推理时 KV Cache 更小，能支持更大的 batch size 和更长的上下文。
`─────────────────────────────────────────────────`

## 五、并行采样与批量推理

### 5.1 多路采样（n > 1）

一次前向传播，可以同时从概率分布中采样多次：

```python
# 一次请求生成 3 个不同的回答
response = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "写一首诗"}],
    n=3,                  # 生成 3 个候选
    temperature=1.0
)
# 返回 3 个不同的诗歌
```

原理：Step 1 对同一份 K、V 做 Attention，得到同一份 logits，然后从中独立采样 3 次，得到 3 个不同的 token。后续每一步各自独立扩展。

### 5.2 批量推理（Batch Inference）

同时处理多个用户的请求：

```
用户 A 的 prompt → [tok₁, tok₂, tok₃]
用户 B 的 prompt → [tok₁, tok₂, tok₃, tok₄, tok₅]
用户 C 的 prompt → [tok₁, tok₂]

用 <pad> 对齐后组成 batch：
[[tok₁, tok₂, tok₃, <pad>, <pad>],
 [tok₁, tok₂, tok₃, tok₄,  tok₅ ],
 [tok₁, tok₂, <pad>, <pad>, <pad>]]

一次前向传播处理整个 batch（GPU 利用率高）
```

批量推理是推理服务（如 vLLM、TensorRT-LLM）的核心优化手段——GPU 大量计算单元在处理单个请求时是闲置的，批量处理能让 GPU 满载。

## 六、自回归 vs 非自回归

### 6.1 对比

| 特性 | 自回归（AR） | 非自回归（NAR） |
|------|------------|----------------|
| 生成方式 | 逐步生成，每步依赖前一步 | 一次性并行生成所有 token |
| 速度 | O(T)，T 是序列长度 | O(1)（理论上） |
| 质量 | 高，token 间有强依赖 | 较低，各 token 独立生成 |
| 应用 | GPT、LLaMA 等文本生成 | 机器翻译（部分）、图像生成（部分） |
| 典型问题 | 速度慢 | 输出不一致（重复、矛盾） |

### 6.2 为什么 LLM 都用自回归？

> 自回归虽然慢，但**生成质量远高于非自回归**。

原因：
1. **语言天然有序**：下一个词的选择强烈依赖前面的内容，自回归建模了这种依赖
2. **训练简单**：Teacher Forcing + 交叉熵损失，训练稳定高效
3. **可扩展**：模型越大、数据越多，自回归模型的生成质量持续提升（scaling law）
4. **工程成熟**：KV Cache、Speculative Decoding 等优化大幅缓解了速度问题

## 七、Speculative Decoding（投机解码）

### 7.1 核心思想

> 用一个**小模型**快速"猜测"几个 token，然后用**大模型一次性验证**——如果猜对了就直接用，猜错了就从错误位置重新开始。

```
传统自回归（大模型逐步生成）：
  Step 1: 大模型 → tok₁ (10ms)
  Step 2: 大模型 → tok₂ (10ms)
  Step 3: 大模型 → tok₃ (10ms)
  Step 4: 大模型 → tok₄ (10ms)
  总计：40ms，生成 4 个 token

投机解码：
  小模型快速猜测：tok₁, tok₂, tok₃, tok₄ (5ms)
  大模型一次性验证全部 4 个 (15ms)
  假设 tok₁, tok₂ 正确，tok₃ 错误
  采纳 tok₁, tok₂，从 tok₃ 位置重新开始
  总计：约 20ms，生成 2~4 个 token（质量不变）
```

### 7.2 为什么质量不变？

> 大模型的验证过程在数学上等价于逐步生成——最终输出的概率分布与传统自回归完全一致。

这不是近似，而是**精确加速**。小模型只是在"试探"，最终决策权在大模型。

## 八、面试高频问题

### Q1：什么是自回归生成？为什么大模型都用这种方式？

> 自回归生成是指模型每次预测下一个 token，然后把生成的 token 拼接到输入中，继续预测下一个，直到生成结束标志。大模型都采用这种方式，因为：（1）语言天然有序，下一个词强烈依赖前面的语境，自回归精确建模了这种依赖关系；（2）训练方式简单高效（Teacher Forcing + 交叉熵）；（3）生成质量远高于非自回归方式。

### Q2：Greedy、Beam Search、Top-p Sampling 分别适合什么场景？

> - **Greedy**：适合确定性输出，如代码生成、事实问答、翻译
> - **Beam Search**：适合目标明确的生成任务，如机器翻译、文本摘要
> - **Top-p**：适合开放性生成任务，如对话、创意写作。目前是主流默认策略，GPT/LLaMA/Qwen 的 API 默认使用

### Q3：Temperature 参数的作用是什么？调高调低分别有什么效果？

> Temperature 控制概率分布的平滑程度。T 越小，分布越"尖锐"（接近 one-hot），输出越确定、越保守；T 越大，分布越"平坦"，输出越随机、越多样。T → 0 等价于 Greedy。实际使用中，创意写作用 T=1.0~1.5，事实问答用 T=0~0.3。

### Q4：什么是 KV Cache？为什么它对推理至关重要？

> KV Cache 是在自回归生成过程中，将每一步计算出的 Key 和 Value 向量缓存起来，下一步只计算新 token 的 Q、K、V，然后复用缓存的 K、V 做 Attention。没有 KV Cache，每一步都要重新计算所有历史 token 的 K、V，推理复杂度为 O(n²)，有 KV Cache 降为 O(n)。这是推理速度的核心优化，也决定了为什么 GQA（减少 KV 头数）对推理效率至关重要。

### Q5：Top-p 和 Top-k 有什么区别？为什么 Top-p 更常用？

> Top-k 固定保留概率最高的 k 个 token，Top-p 保留概率累积达到 p 的最小集合（大小自适应）。Top-p 的优势在于：当分布很集中时（如某 token 概率 0.95），自动只保留 1~2 个候选；当分布平坦时，保留更多候选。而 Top-k 在这两种情况下都保留固定数量，不够灵活。

### Q6：什么是 Speculative Decoding？它的原理是什么？

> 用小模型快速生成若干候选 token，然后用大模型一次性验证。大模型的验证在数学上等价于逐步自回归生成，所以输出质量完全不变。速度提升来自：小模型生成 N 个 token 的时间 << 大模型生成 N 个 token 的时间，而大模型一次性验证 N 个 token 的时间 ≈ 大模型生成 1 个 token 的时间。

### Q7：推理时的显存主要消耗在哪里？

> 三个主要部分：（1）模型参数（最大）——FP16 下 70B 模型约 140GB；（2）KV Cache——随序列长度和 batch size 增长，GQA 有效降低此项；（3）激活值（中间计算结果）——batch 推理时较大。优化方向：参数量化（INT8/INT4）、GQA 减小 KV Cache、PagedAttention 管理显存。

### Q8：repetition_penalty 是什么？它和其他解码参数的执行顺序是怎样的？

> repetition_penalty 对已出现 token 的 logits 施加惩罚（>1 压低概率，<1 鼓励重复），用于抑制生成文本中的重复现象。执行顺序：（1）先施加 repetition_penalty（logits 层面）；（2）再用 temperature 缩放；（3）最后用 top-p / top-k 过滤候选。这个顺序决定了每个参数的生效逻辑——repetition_penalty 在 logits 上直接修改，temperature 和 top-p 在概率分布上操作。

## 九、总结

**自回归生成的核心链路一句话总结**：

> 给定 prompt，逐步预测下一个 token 的概率分布，用解码策略从中选出 token，拼接到序列末尾，重复直到结束。KV Cache 复用历史计算加速推理，解码策略控制生成的多样性和质量。

**关键要点**：

| 要点 | 说明 |
|------|------|
| 自回归本质 | 每步预测下一个 token，逐步拼接，串行生成 |
| 训练 vs 推理 | 训练并行（Teacher Forcing），推理串行（逐步生成） |
| 解码策略 | Greedy（快但死板）、Beam Search（质量高但慢）、Top-p（主流，自适应） |
| Temperature | 控制分布尖锐度，T 低→保守，T 高→多样 |
| Repetition Penalty | 惩罚已出现 token，抑制重复，logits 层面最先执行 |
| KV Cache | 缓存历史 K、V，推理加速的核心 |
| GQA | 减少 KV 头数，KV Cache 降到 1/g，推理显存大幅节省 |
| Speculative Decoding | 小模型猜测 + 大模型验证，精确加速不降质量 |

**从输入到输出的完整链路**：

```
用户输入 "你是谁"
  → Tokenizer 分词 → [10892, 5398]
  → Embedding → [v₁, v₂]
  → Transformer（Masked Attention + KV Cache）→ logits
  → Repetition Penalty（惩罚已出现 token）
  → Temperature 缩放
  → Top-p / Top-k 过滤
  → 采样 → token ID
  → 追加到序列 → 继续下一步
  → 遇到 <|eos|> 或 max_tokens → 停止
  → Tokenizer 解码所有 token ID → "我是一个AI助手"
```
