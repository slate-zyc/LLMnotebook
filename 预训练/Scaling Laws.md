# Scaling Laws（缩放定律）

> 前面讲了 Transformer 怎么工作、预训练数据怎么处理，但还有一个关键问题：**模型要多大？数据要多少？算力要花多少？** Scaling Laws 就是回答这些问题的经验规律——它告诉你，在训练预算有限时，应该把钱花在模型规模还是数据规模上。

---

## 一、什么是 Scaling Laws

### 1.1 核心定义

Scaling Laws 描述的是：**模型性能（Loss）与模型参数量（N）、数据量（D）、计算量（C）之间的幂律关系。**

简单说：当你增加模型规模或数据量时，模型的损失（Loss）会按照某个规律下降。

### 1.2 Kaplan 的发现（OpenAI, 2020）

OpenAI 在论文 *Scaling Laws for Neural Language Models* 中发现：

$$L(N) = \left(\frac{N_c}{N}\right)^{\alpha_N}, \quad L(D) = \left(\frac{D_c}{D}\right)^{\alpha_D}, \quad L(C) = \left(\frac{C_c}{C}\right)^{\alpha_C}$$

其中：
- $L$ 是测试集 Loss（越低越好）
- $N$ 是模型参数量
- $D$ 是训练数据量（token 数）
- $C$ 是计算量（FLOPs）
- $\alpha_N, \alpha_D, \alpha_C$ 是幂律指数

**关键发现**：

| 结论 | 含义 |
|------|------|
| 性能与 N、D、C 都呈幂律关系 | 增加任何一个都能稳定提升性能 |
| 三者之间存在最优分配 | 给定计算预算 C，N 和 D 要按比例分配 |
| 小模型 + 大数据 ≈ 大模型 + 小数据 | 但最优策略是两者都大 |

### 1.3 Chinchilla 的修正（DeepMind, 2022）

Kaplan 的结论有一个问题：**它建议用更大的模型但较少的数据**。DeepMind 的 Chinchilla 论文（*Training Compute-Optimal Large Language Models*）修正了这个结论：

**Chinchilla 的核心发现**：

| Kaplan 的建议 | Chinchilla 的建议 |
|--------------|------------------|
| 模型参数 N 和计算量 C 的最优关系：$N \propto C^{0.73}$ | **模型参数 N 和数据量 D 应该同比例增长** |
| 偏向大模型、少数据 | **N 和 D 的比例应该约为 1:20**（20 tokens per parameter） |

**具体数字**：

```
如果模型有 1B 参数，最优训练数据量约为 20B tokens
如果模型有 7B 参数，最优训练量约为 140B tokens
如果模型有 70B 参数，最优训练量约为 1.4T tokens
```

`★ Insight ─────────────────────────────────────`
Chinchilla 定律的意义：LLaMA 7B 用 1T tokens 训练，远超 Chinchilla 最优的 140B tokens。这不是浪费，而是 **Over-training**——为了推理效率（小模型推理更快），故意用更多数据训练较小的模型。
`─────────────────────────────────────────────────`

## 二、三个 Scaling 维度

### 2.1 模型规模 Scaling（N）

增加模型参数量：

| 参数量 | 典型模型 | 特点 |
|--------|---------|------|
| 1B-3B | GPT-2 Small, Phi-2 | 端侧部署，能力有限 |
| 7B-13B | LLaMA 7B, Mistral 7B | 消费级显卡可跑，性价比高 |
| 70B-72B | LLaMA 2 70B, Qwen 72B | 需要多卡，能力强 |
| 405B+ | LLaMA 3 405B, GPT-4 | 顶级能力，训练成本极高 |

**Scaling 表现**：

```
模型参数量 ×10 → Loss 下降约 0.3-0.5（对数尺度下线性）

7B  → Loss 2.8
70B → Loss 2.3（下降 0.5）
```

### 2.2 数据规模 Scaling（D）

增加训练数据量：

| 数据量 | 典型案例 | 说明 |
|--------|---------|------|
| 10B tokens | 早期小模型 | 数据不够，欠拟合 |
| 100B tokens | LLaMA 1（部分模型） | 中等规模 |
| 1T tokens | LLaMA 1/2 主力 | 主流选择 |
| 2T+ tokens | LLaMA 3, Qwen 2.5 | Over-training，追求更好效果 |

**Scaling 表现**：

```
数据量 ×10 → Loss 下降约 0.2-0.3

100B tokens → Loss 2.9
1T tokens   → Loss 2.6（下降 0.3）
```

### 2.3 计算规模 Scaling（C）

计算量 = 模型参数 × 数据量 × 6（前向+反向传播的 FLOPs 估算）：

$$C \approx 6 \cdot N \cdot D$$

| 计算量 | 典型模型 | 训练成本估算 |
|--------|---------|-------------|
| $10^{21}$ FLOPs | 7B × 1T tokens | ~$100K |
| $10^{22}$ FLOPs | 70B × 1T tokens | ~$1M |
| $10^{23}$ FLOPs | 405B × 15T tokens | ~$100M+ |

## 三、最优分配策略

### 3.1 给定预算，如何分配？

**核心问题**：你有固定的计算预算 C（比如 $10^{22}$ FLOPs），应该训练一个大模型用少量数据，还是小模型用大量数据？

**Chinchilla 的答案**：

$$N_{opt} \propto C^{0.5}, \quad D_{opt} \propto C^{0.5}$$

即 **模型参数和数据量应该同比例增长**。

**具体分配表**：

| 计算预算 C | 最优参数量 N | 最优数据量 D | 比例 D/N |
|-----------|-------------|-------------|---------|
| $10^{21}$ | 3B | 60B tokens | 20:1 |
| $10^{22}$ | 10B | 200B tokens | 20:1 |
| $10^{23}$ | 30B | 600B tokens | 20:1 |
| $10^{24}$ | 100B | 2T tokens | 20:1 |

### 3.2 为什么不选极端方案？

**方案 A：超大模型 + 极少数据**

```
70B 参数 + 10B tokens → 严重欠拟合，浪费模型容量
```

- 模型有很强的"学习能力"，但没有足够的"教材"
- 就像请了顶级教授但只给他看10页书

**方案 B：极小模型 + 海量数据**

```
100M 参数 + 10T tokens → 严重过拟合，模型容量不足
```

- 模型"学习能力"有限，数据再多也记不住
- 就像让小学生学完整个图书馆，能力天花板太低

**方案 C：均衡分配（Chinchilla 最优）**

```
10B 参数 + 200B tokens → 性能最优，性价比最高
```

### 3.3 实际工程中的权衡

| 考虑因素 | 偏好小模型 | 偏好大数据 |
|---------|-----------|-----------|
| **推理成本** | ✅ 小模型推理快、便宜 | ❌ 大模型推理慢、贵 |
| **训练效率** | ❌ 需要更多数据，训练时间长 | ✅ 大模型收敛快 |
| **部署场景** | ✅ 端侧/边缘部署 | ❌ 只能云端部署 |
| **实验迭代** | ✅ 小模型调参快 | ❌ 大模型实验成本高 |

`★ Insight ─────────────────────────────────────`
实际工程中，大多数团队选择 **Over-training**（偏离 Chinchilla 最优点，用更多数据训练较小模型）。原因是：训练是一次成本，推理是持续成本。一个小模型部署后每天节省的推理费用，远超训练时多花的钱。
`─────────────────────────────────────────────────`

## 四、Scaling Laws 的局限性

### 4.1 只预测 Loss，不预测能力

Scaling Laws 预测的是**训练 Loss**，但用户关心的是**下游任务能力**（推理、代码、数学等）。

**Emergent Abilities（涌现能力）**：

某些能力在模型规模达到临界点前几乎为零，超过临界点后突然出现：

| 能力 | 涌现规模（大约） |
|------|----------------|
| Few-shot CoT 推理 | ~100B 参数 |
| 复杂代码生成 | ~70B 参数 |
| 多步数学推理 | ~70B+ 参数 |

但也有争议：有研究认为"涌现"只是评估指标的假象（用连续指标而非离散指标，涌现就消失了）。

### 4.2 数据质量的影响

Scaling Laws 假设数据质量恒定，但实际中：

```
高质量数据 ×1T tokens  >>  低质量数据 ×10T tokens
```

数据质量可以改变 Scaling 曲线的斜率——高质量数据让每单位数据的价值更高。

### 4.3 架构的影响

Scaling Laws 是基于特定架构（Transformer）的经验规律。如果换架构（如 Mamba、RWKV），Scaling 行为可能不同。

## 五、面试高频问题

### Q1：什么是 Scaling Laws？它有什么用？

> Scaling Laws 是描述模型性能（Loss）与模型规模（N）、数据量（D）、计算量（C）之间幂律关系的经验规律。它的用处：(1) 预测模型训练需要多少资源；(2) 给定预算时决定模型和数据的最优分配；(3) 评估新架构或新数据的潜在收益。

### Q2：Chinchilla 定律和 Kaplan 的结论有什么区别？

> Kaplan（2020）建议优先增大模型参数量，N 和 C 的关系是 $N \propto C^{0.73}$。Chinchilla（2022）修正了这个结论，发现**模型参数和数据量应该同比例增长**，最优比例约为 1:20（每个参数对应 20 个训练 token）。Chinchilla 更强调数据的重要性。

### Q3：为什么 LLaMA 7B 用 1T tokens 训练，远超 Chinchilla 最优的 140B？

> 这是**故意 Over-training**。Chinchilla 最优是"训练时成本最低"的点，但实际工程还要考虑推理成本。LLaMA 7B 推理时比 70B 快 10 倍，即使训练多花了一些数据，部署后的推理节省远超训练成本。这是工程上的权衡，不是理论错误。

### Q4：给定 $10^{22}$ FLOPs 的预算，按照 Chinchilla 应该怎么分配？

> 按 $N_{opt} \propto C^{0.5}, D_{opt} \propto C^{0.5}$，以及 $D/N \approx 20$ 的比例：最优参数量约 10B，训练数据量约 200B tokens。这样能在给定预算下获得最低的 Loss。

### Q5：Scaling Laws 能预测模型的下游任务能力吗？

> Scaling Laws 直接预测的是训练 Loss，不直接预测下游任务准确率。但 Loss 和下游能力有相关性——通常 Loss 越低，下游任务表现越好。某些能力（如 CoT 推理）表现出"涌现"特性，需要模型规模达到临界点才能出现。

### Q6：影响 Scaling 的因素除了 N、D、C 还有什么？

> (1) **数据质量**——高质量数据能让 Scaling 曲线更陡（每单位数据收益更高）；(2) **数据分布**——不同领域的数据混合比例会影响不同任务的 Scaling；(3) **模型架构**——MoE、GQA 等架构改变可能影响 Scaling 行为；(4) **训练超参数**——学习率、batch size 等也会影响实际 Scaling 效果。

## 六、总结

| 概念 | 核心要点 |
|------|---------|
| Scaling Laws | 性能与 N、D、C 呈幂律关系 |
| Chinchilla 最优 | N 和 D 同比例增长，比例约 1:20 |
| Over-training | 工程中常用策略，用更多数据训练小模型以降低推理成本 |
| 局限性 | 只预测 Loss，不直接预测能力；数据质量影响大 |

**一句话记忆**：

> Scaling Laws 告诉你"大力出奇迹"的规律，Chinchilla 告诉你"力要出在刀刃上"——模型和数据要一起长大。
