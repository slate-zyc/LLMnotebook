# 预训练数据工程

> Scaling Laws 告诉你模型和数据要一起长大，但**数据从哪来？质量怎么保证？** 模型的能力上限由数据决定——"Garbage in, garbage out"。本文讲清楚预训练数据的获取、清洗、去重、配比的全流程。

---

## 一、预训练数据的来源

### 1.1 主要数据源

| 数据源 | 规模 | 特点 | 代表数据集 |
|--------|------|------|-----------|
| **网页数据** | 万亿级 token | 规模大、噪声多、覆盖广 | Common Crawl, C4 |
| **书籍** | 百亿级 token | 质量高、长文本、知识密集 | Books3, Gutenberg |
| **代码** | 千亿级 token | 逻辑性强、结构化 | GitHub, The Stack |
| **学术论文** | 百亿级 token | 专业性强、格式规范 | arXiv, S2ORC |
| **百科/知识库** | 十亿级 token | 事实准确、解释清晰 | Wikipedia |
| **对话/论坛** | 千亿级 token | 口语化、多轮对话 | Reddit, StackExchange |
| **多语言** | 变化大 | 覆盖非英语语言 | CC-100, OPUS |

### 1.2 典型数据配比

不同模型的数据配比差异很大，以 LLaMA 系列为参考：

| 数据类型 | LLaMA 1 | LLaMA 2 | LLaMA 3 | 说明 |
|---------|---------|---------|---------|------|
| 网页数据 | 67% | 80% | 50% | 主体，但比例在下降 |

| 多语言 | 17% | 8% | 33% | LLaMA 3 大幅增加 |

`★ Insight ─────────────────────────────────────`
**趋势观察**：代码数据的比例从 4.5% 上升到 17%，原因是代码数据能显著提升模型的逻辑推理能力——即使你不打算用模型写代码。代码中蕴含的"如果...那么..."逻辑结构，对所有推理任务都有帮助。

## 二、数据清洗流程

### 2.1 清洗流水线

```
原始网页数据
    ↓
┌─────────────────────────────────────────────┐
│ 第一步：格式清洗（Format Cleaning）          │
│   - HTML 标签移除                           │
│   - 特殊字符处理                            │
│   - 编码统一（UTF-8）                        │
└─────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────┐
│ 第二步：质量过滤（Quality Filtering）        │
│   - 语言识别（过滤非目标语言）               │
│   - 规则过滤（长度、重复率、特殊字符比例）    │
│   - 模型过滤（用分类器打分）                 │
└─────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────┐
│ 第三步：去重（Deduplication）                │
│   - 精确去重（URL/哈希）                     │
│   - 模糊去重（MinHash/SimHash）             │
│   - 语义去重（Embedding 相似度）             │
└─────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────┐
│ 第四步：安全过滤（Safety Filtering）         │
│   - 有害内容过滤                            │
│   - PII（个人身份信息）移除                  │
│   - 版权敏感内容处理                        │
└─────────────────────────────────────────────┘
    ↓
干净的预训练数据
```

### 2.2 格式清洗

**HTML 标签移除**：

```python
# 简单示例
import re

def clean_html(text):
    # 移除 HTML 标签
    text = re.sub(r'<[^>]+>', '', text)
    # 移除多余空白
    text = re.sub(r'\s+', ' ', text)
    # 移除特殊字符
    text = re.sub(r'[^\w\s.,!?;:\'-]', '', text)
    return text.strip()
```

**常见问题**：

| 问题 | 示例 | 处理方式 |
|------|------|---------|
| HTML 标签 | `<p>Hello</p>` | 正则移除 |
| JavaScript 代码 | `var x = 1;` | 规则检测并移除 |
| 编码错误 | `Ã©` (é 的错误编码) | 编码统一为 UTF-8 |
| 特殊 Unicode | 控制字符、零宽字符 | 移除或替换 |

### 2.3 质量过滤

**规则过滤（基于启发式规则）**：

| 规则 | 阈值 | 说明 |
|------|------|------|
| 文档长度 | 100-100000 字符 | 太短没信息量，太长可能有问题 |
| 字母比例 | > 80% | 过滤纯数字/符号页面 |
| 句号比例 | > 10% | 过滤列表、目录类页面 |
| 停用词比例 | > 某阈值 | 过滤非自然语言文本 |
| 行重复率 | < 50% | 过滤模板化内容 |
| 特殊字符比例 | < 20% | 过滤乱码页面 |

**模型过滤（用分类器打分）**：

```python
# 思路：用一个在高质量数据上训练的分类器，给每个文档打分

# 1. 准备正负样本
# 正样本：Wikipedia、书籍等高质量文本
# 负样本：随机网页、垃圾页面

# 2. 训练二分类器（如 fastText）
# 3. 对每个文档预测"高质量"的概率
# 4. 保留概率 > 阈值的文档

# LLaMA 使用的方法：
# - 训练一个二分类器区分 Wikipedia 文档 vs 随机网页
# - 保留分类器认为"更像 Wikipedia"的文档
```

`★ Insight ─────────────────────────────────────`
**Gopher 规则**（DeepMind）：用一组精心设计的启发式规则过滤，包括：
- 平均单词长度 > 3
- 平均句子长度 > 20 单词
- 90% 的行以标点结尾（排除代码/列表）

这些简单规则在实践中效果很好，被许多模型采用。

## 三、数据去重

### 3.1 为什么要去重？

| 问题 | 影响 |
|------|------|
| **训练效率** | 重复数据浪费算力，模型反复看相同内容 |
| **记忆化** | 模型可能逐字记住训练数据，导致隐私泄露 |
| **评估污染** | 训练数据和测试集重叠，评估结果不可信 |
| **分布偏移** | 重复数据会扭曲数据分布 |

**实验证据**：有研究发现，去重后用 1T tokens 训练的效果，相当于去重前用 3T tokens 训练的效果——**去重能让数据价值提升 3 倍**。

### 3.2 去重方法

#### 精确去重（Exact Deduplication）

| 方法 | 粒度 | 实现 |
|------|------|------|
| URL 去重 | 文档级 | 同一 URL 只保留一份 |
| 哈希去重 | 文档/段落级 | MD5/SHA256 相同则去重 |
| 行级去重 | 行级 | 完全相同的行只保留一份 |

**优点**：快速、准确
**缺点**：只能处理完全相同的副本，稍有修改就漏掉

#### 模糊去重（Fuzzy Deduplication）

**MinHash + LSH（Locality-Sensitive Hashing）**：

```
核心思想：把文档转换为"指纹集合"，用 MinHash 快速估算相似度

步骤：
1. 文档 → shingle（n-gram）集合
   "hello world" → {"hel", "ell", "llo", "lor", "orl", "rld"}

2. 每个 shingle → 哈希值
   {"hel", "ell", ...} → {3421, 8823, ...}

3. MinHash 签名（固定长度的哈希子集）
   原始集合 {3421, 8823, 1234, 5678, ...}
   MinHash   → [3421, 1234, 5678]（取每个 band 的最小值）

4. LSH 分桶
   相似文档的 MinHash 签名大概率落入同一桶

5. 桶内文档两两比较 Jaccard 相似度
   相似度 > 阈值（如 0.8）→ 去重
```

**参数选择**：

| 参数 | 典型值 | 影响 |
|------|--------|------|
| Shingle 大小 | 5-13 | 越大越严格 |
| MinHash 签名长度 | 128-256 | 越长越准确 |
| LSH bands | 9-20 | 越多越敏感 |
| 相似度阈值 | 0.7-0.9 | 越高保留越多 |

#### 语义去重（Semantic Deduplication）

```python
# 思路：用 Embedding 模型计算文档语义相似度

# 1. 用 Sentence-BERT 等模型编码每个文档
embeddings = model.encode(documents)

# 2. 构建近似最近邻索引（FAISS）
index = faiss.IndexIVFFlat(embedding_dim, nlist=100)
index.add(embeddings)

# 3. 对每个文档，找到最相似的 K 个邻居
# 4. 如果与某邻居的相似度 > 阈值，去重

# 优点：能处理"内容相似但措辞不同"的情况
# 缺点：计算成本高，需要 GPU
```

### 3.3 去重粒度

| 粒度 | 方法 | 适用场景 |
|------|------|---------|
| URL 级 | 精确 | 网页数据初步去重 |
| 文档级 | MinHash/哈希 | 主要去重手段 |
| 段落级 | MinHash | 处理拼接文档 |
| 语义级 | Embedding | 高质量去重，成本高 |

`★ Insight ─────────────────────────────────────`
**去重的两难**：去重太狠会丢失有价值的多样性（比如同一话题的不同观点），去重太松会保留太多重复。实际操作中，**文档级 MinHash 去重**是性价比最高的选择，大多数开源模型都用这种方法。

## 四、数据配比与调度

### 4.1 数据配比（Data Mix）

不同来源的数据按什么比例混合：

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **均匀采样** | 各来源等比例 | 简单 | 小数据源被过度采样 |
| **温度采样** | 按数据量的 $1/T$ 次方采样 | 平衡大小源 | 需要调 T |
| **能力导向** | 根据目标能力调整 | 定制化强 | 需要人工设计 |

**温度采样（Temperature Sampling）**：

$$p_i = \frac{n_i^{1/T}}{\sum_j n_j^{1/T}}$$

其中 $n_i$ 是来源 $i$ 的数据量，$T$ 是温度参数：
- $T = 1$：按原始比例采样
- $T = \infty$：均匀采样（所有来源等权重）
- $T = 2$：常用折中值

### 4.2 数据调度（Data Curriculum）

**课程学习（Curriculum Learning）**：先简单后困难

```
训练初期：高质量、简单数据（Wikipedia、书籍）
    ↓
训练中期：中等质量数据（新闻、文章）
    ↓
训练后期：大规模网页数据（包含噪声）
```

**实践中的发现**：

| 观点 | 支持证据 |
|------|---------|
| 课程学习有效 | 一些研究发现先用简单数据能加速收敛 |
| 课程学习无效 | LLaMA 等主流模型都用随机打乱，效果也很好 |
| **结论** | 数据质量比课程顺序更重要 |

### 4.3 数据混合的 Scaling

```
核心发现：不同数据配比会改变 Scaling 行为

代码数据多 → 数学、推理能力 Scaling 更好
多语言数据多 → 跨语言能力 Scaling 更好
对话数据多 → 对话能力 Scaling 更好
```

## 五、数据质量评估

### 5.1 自动评估指标

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **困惑度（Perplexity）** | 用参考模型计算 | 越低说明越像"正常文本" |
| **分类器得分** | 质量分类器的概率 | 越高说明质量越好 |
| **重复率** | n-gram 重复比例 | 越低说明越多样 |
| **平均句长** | 总词数 / 句子数 | 过短/过长都可能有问题 |

### 5.2 人工评估

| 方法 | 做法 | 适用场景 |
|------|------|---------|
| **随机抽样** | 随机抽取文档人工检查 | 快速质检 |
| **对比评估** | 对比不同清洗策略的效果 | 评估清洗策略 |
| **专家评审** | 领域专家评估数据质量 | 高质量要求场景 |

### 5.3 质量-多样性权衡

```
高质量 + 低多样性 → 模型能力窄，泛化差
低质量 + 高多样性 → 模型学不到有用知识
高质量 + 高多样性 → 理想状态，但难以兼得

实际策略：宁可牺牲一点质量，也要保证足够的多样性
```

## 六、面试高频问题

### Q1：预训练数据的清洗流程是什么？

> 主要分四步：(1) **格式清洗**——移除 HTML 标签、统一编码、处理特殊字符；(2) **质量过滤**——用规则（长度、重复率等）和模型（分类器打分）过滤低质量文档；(3) **去重**——用 MinHash+LSH 等方法移除重复文档；(4) **安全过滤**——移除有害内容和 PII。

### Q2：为什么要做数据去重？不去重会有什么问题？

> 去重的原因：(1) **训练效率**——重复数据浪费算力，去重后 1T tokens 效果可抵 3T；(2) **记忆化风险**——模型可能逐字记住训练数据，导致隐私泄露；(3) **评估污染**——训练集和测试集重叠会让评估不可信；(4) **分布偏移**——重复数据扭曲真实分布。

### Q3：MinHash 去重的原理是什么？

> MinHash 把文档转换为 shingle（n-gram）集合，然后用哈希函数采样生成固定长度的签名。相似文档的签名大概率相似，通过 LSH（局部敏感哈希）分桶后，只需比较桶内文档，大幅降低计算量。典型参数：shingle=5-13，签名长度=128-256，相似度阈值=0.8。

### Q4：如何决定不同数据源的配比？

> 常用温度采样：$p_i = n_i^{1/T} / \sum n_j^{1/T}$。$T=1$ 按原始比例，$T=\infty$ 均匀采样，$T=2$ 是常用折中。实际中还要考虑目标能力：想提升推理能力就多加代码数据，想提升多语言能力就多加多语言数据。LLaMA 3 的代码比例从 4.5% 提升到 17%，推理能力显著提升。

### Q5：Over-training 和 Chinchilla 最优有什么关系？

> Chinchilla 最优是"训练成本最低"的点（N:D=1:20），但实际工程要综合考虑推理成本。Over-training 是故意用更多数据（如 LLaMA 7B 用 1T tokens）训练较小模型，虽然训练不是最优，但部署后推理更快更便宜，总体成本更低。

### Q6：数据质量 vs 数据数量，哪个更重要？

> **同等重要，但质量是基础**。Scaling Laws 假设数据质量恒定，如果质量差，数量再多也难弥补。实验证据：高质量数据 1T tokens 可以胜过低质量数据 10T tokens。但在质量保证的前提下，增加数量确实能稳定提升性能。最佳策略是"高质量数据 + 足够数量 + 合理配比"。

## 七、总结

| 环节 | 核心要点 |
|------|---------|
| 数据来源 | 网页为主，代码比例在上升 |
| 格式清洗 | HTML 移除、编码统一 |
| 质量过滤 | 规则 + 分类器，保留高质量文档 |
| 数据去重 | MinHash+LSH 是主流方案 |
| 数据配比 | 温度采样，平衡大小源 |

**一句话记忆**：

> 预训练数据工程就是"从互联网淘金"——先挖出来（采集），再洗掉沙子（清洗），去掉重复的（去重），按比例混合（配比），最后喂给模型。
